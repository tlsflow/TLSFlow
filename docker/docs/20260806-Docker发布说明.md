# GCAC Docker 发布说明

## 构建前置条件

主机只需要安装 Docker、Docker Compose v2 和 Buildx，不要求宿主机安装 Go。公开仓库不提交 `agents/*/dist` 目录，Docker 构建脚本会先启动 `Dockerfile.agent-release-bundle` builder 容器，在容器内自动配置 Go 1.23 Full Agent 和 Go 1.20 Compatibility Agent，生成完整发布包后再构建业务镜像。`gcac-small` 和 `gcac-web` 会在 Docker 构建阶段使用 VitePress 生成并打包 `docs/Documentation` 在线文档，宿主机不需要预先生成 `.vitepress/dist`。

`build-local.mjs`、交互式 `build-docker.mjs` 和发布脚本会在镜像构建前自动调用 Agent builder。直接执行 `build-agent-release-bundle.mjs` 时，脚本会优先使用宿主机的 Go；如果 Go 不可用或 Compatibility 产物不完整，则自动转交 Docker builder。需要强制使用宿主机工具链时，要求 Go 1.23.x 或更高版本；如果默认 `go` 是 Compatibility 所需的 Go 1.20.x，必须显式指定 Full Agent 工具链：

```text
GCAC_FULL_GO=/usr/local/go/bin/go node docker/build-tools/build-agent-release-bundle.mjs
```

该脚本会构建并输出：

- Linux amd64、arm64 Go Agent；
- Windows amd64、arm64 Go Agent；
- Windows Compatibility Agent 安装资源；
- `manifest.json` 及每个文件的 SHA256。

如果 Windows Compatibility Agent 的构建产物不存在，脚本会失败。不能把源码目录直接复制进生产镜像。

公开仓库只支持纯本地构建，不保存 Docker Hub 凭据，也不自动推送镜像：

```text
node docker/build-tools/build-local.mjs --architecture small
node docker/build-tools/build-local.mjs --architecture standard
```

Agent 发布包构建默认使用 `https://proxy.golang.org`，当该代理的 TLS
证书在当前网络环境中无法验证时，自动按顺序尝试 `https://goproxy.cn` 和
`direct`。Go 模块仍使用各 Agent 目录中的 `go.sum` 校验，不会关闭模块完整性
校验。需要指定企业内部 Go 代理时，可通过构建前环境变量覆盖：

```text
GCAC_GO_PROXY="https://your-go-proxy|https://goproxy.cn|direct" node docker/build-tools/build-local.mjs --architecture small
```

也可以在仓库根目录使用交互式入口，通过列表中的数字选择全部镜像或单个镜像：

```text
node docker/build-docker.mjs
node docker/build-docker.mjs --all
node docker/build-docker.mjs --image gcac-backend
```

Compose 环境变量模板位于 `docker/.env.example`，只用于 standard 部署。复制为
`docker/.env` 后填写 Docker Hub 命名空间、镜像标签、数据库密码和 GCAC 密钥，
然后在 `docker` 目录直接执行 `docker compose up -d`。Compose 文件不包含 small
服务，也不要求宿主机安装 Node.js。

Plugin Runner、Policy Authority 和 Agent Local Policy 的实例级信任材料不再写入
公开模板或镜像。生产容器首启会使用 `GCAC_SECRET_KEK` 派生加密密钥，随机生成
Ed25519 信任根、签名 KeySet、Bootstrap 和失败关闭的初始策略包，并将密文原子写入
`/app/data/runtime/runtime-secrets.enc`。该目录由 Compose 持久化；同时保存
`policy-authority-state.json`。后续重启只解密同一份材料，不能更换
`GCAC_SECRET_KEK`，否则服务会失败关闭。删除运行时卷会重新生成全新的信任根。

本地构建使用 `docker buildx build --load`，镜像只进入当前主机 Docker。Docker Hub 多架构发布由受控发布流水线调用 `docker/publish/publish-images.mjs` 完成；公开仓库不保存 Docker Hub 凭据，也不自动推送镜像。

## 小型版

```bash
docker run -d \
  --name tlsflow-small \
  --restart unless-stopped \
  --label com.gcac.deployment.architecture=small \
  -p 8085:3003 \
  -e GCAC_TOKEN_SECRET=TLSFlow-Token-K4r8-Np2z-2026 \
  -e GCAC_SECRET_KEK=TLSFlow-KEK-H7s3-Lx6v-2026 \
  -v /path/to/data/pglite:/var/lib/gcac/pglite \
  -v /path/to/data/workflows:/app/data/workflows \
  -v /path/to/data/runtime:/app/data/runtime \
  -v /path/to/data/tls-inspector:/app/data/tls-inspector \
  -v /path/to/data/plugins:/app/data/plugins:ro \
  your-dockerhub-namespace/gcac-small:<tag>
```

小型版只有一个服务容器，Backend 使用 PGlite，前端由 Backend 静态托管。PGlite、工作流、运行时和 TLS Inspector 数据分别保存到 `data/pglite/`、`data/workflows/`、`data/runtime/` 和 `data/tls-inspector/`；用户插件保存到 `data/plugins/`。

小型版镜像构建阶段会检查：

- 生产依赖已使用 `npm ci --omit=dev`；
- Agent Release Bundle 的 SHA256；
- 按目标架构内置 `lego 5.3.1`，下载包 SHA-256 必须与 `docker/build-tools/versions.json` 登记值一致，并执行 `lego --version`；
- 镜像中不存在 Chromium、Xvfb、x11vnc、noVNC、websockify 或 Playwright 浏览器依赖。

## 标准版

标准版包含 `db`、`backend`、`web` 和 `browser-runtime` 四个服务：

```bash
cd docker
docker compose pull
docker compose up -d
```

`GCAC_RELEASE_VERSION` 由 `docker/.env` 提供，建议使用固定发布标签。需要 Browser
Runtime 时追加 `--profile browser-runtime`。

Backend 使用 `npm start`，先执行迁移，迁移失败时不会启动 API。Browser Runtime 不挂载 Docker Socket，Compose 中固定了只读根文件系统、归属 `browser-runtime` 用户的临时会话目录、能力丢弃、PID、内存和 CPU 限制。

标准版和小型版的后端运行时镜像均内置 `lego 5.3.1`。构建仅允许 `linux/amd64` 和 `linux/arm64`，下载前从 `docker/build-tools/versions.json` 读取固定资产名和 SHA-256；下载后校验摘要并执行 `lego --version`。运行时默认使用 `/usr/local/bin/lego`，可通过 `GCAC_LEGO_PATH` 覆盖为受控自定义路径，不会在后端启动时联网安装。

Browser Runtime 仅通过 Docker 内部网络暴露 `8787`。`gcac-web` 的 Nginx 只代理 `/vnc/` 路径，并支持 WebSocket 升级，CDP 与 RFB 端口不会映射到宿主机。默认将 `BROWSER_RUNTIME_PUBLIC_BASE_URL` 留空，Runtime 返回同源 `/vnc/...` 地址；如由外部反向代理承载该路径，再将其设置为受保护的公开基础地址。

Runtime 镜像包含 Chromium、Xvfb、Fluxbox 和 x11vnc。构建阶段只从 Debian `novnc` 包提取 noVNC 静态资源，最终镜像不保留其 Python/websockify 运行依赖；WebSocket 到本地 RFB 的桥接由 Runtime 的 Node 服务提供。

标准版 PostgreSQL、工作流、运行时和 TLS Inspector 数据默认分别保存到
`docker/data/postgres/`、`docker/data/workflows/`、`docker/data/runtime/` 和
`docker/data/tls-inspector/`，不会写入镜像。

用户插件包可放在 `docker/data/plugins/<pluginId>/`，Compose 会以只读方式挂载到
`/app/data/plugins`。管理员点击插件市场“刷新市场”时，宿主按当前租户扫描该目录并
通过 USER 导入链注册；仍需完成权限审批、启用和 Binding 配置。
