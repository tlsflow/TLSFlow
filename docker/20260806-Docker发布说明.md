# GCAC Docker 发布说明

## 构建前置条件

先生成 Agent Release Bundle：

```text
node docker/build-agent-release-bundle.mjs
```

该脚本会构建并输出：

- Linux amd64、arm64 Go Agent；
- Windows amd64、arm64 Go Agent；
- Windows Compatibility Agent 安装资源；
- `manifest.json` 及每个文件的 SHA256。

如果 Windows Compatibility Agent 的构建产物不存在，脚本会失败。不能把源码目录直接复制进生产镜像。

公开仓库只支持纯本地构建，不保存 Docker Hub 凭据，也不自动推送镜像：

```text
node docker/build-local.mjs --architecture small
node docker/build-local.mjs --architecture standard
```

本地构建使用 `docker buildx build --load`，镜像只进入当前主机 Docker。Docker Hub 多架构发布由私有发布仓库调用 `docker/publish-images.mjs` 完成，具体边界见 [20260806-公开仓库与私有发布仓库说明.md](C:/Code/GCAC/docker/20260806-公开仓库与私有发布仓库说明.md)。

## 小型版

```text
docker compose --env-file docker/versions.env --profile small -f docker/compose.yml up -d --build
```

小型版只有一个服务容器，Backend 使用 PGlite，前端由 Backend 静态托管。PGlite 数据持久化到 `gcac_small_pglite`，用户 Workflow 持久化到 `gcac_small_workflows`。

小型版镜像构建阶段会检查：

- 生产依赖已使用 `npm ci --omit=dev`；
- Agent Release Bundle 的 SHA256；
- 镜像中不存在 Chromium、Xvfb、x11vnc、noVNC、websockify 或 Playwright 浏览器依赖。

## 标准版

标准版包含 `db`、`backend`、`web` 和 `browser-runtime` 四个服务：

```text
docker compose --env-file docker/versions.env --profile standard -f docker/compose.yml up -d --build
```

Backend 使用 `npm start`，先执行迁移，迁移失败时不会启动 API。Browser Runtime 不挂载 Docker Socket，Compose 中固定了只读根文件系统、归属 `browser-runtime` 用户的临时会话目录、能力丢弃、PID、内存和 CPU 限制。

Browser Runtime 仅通过 Docker 内部网络暴露 `8787`。`gcac-web` 的 Nginx 只代理 `/vnc/` 路径，并支持 WebSocket 升级，CDP 与 RFB 端口不会映射到宿主机。默认将 `BROWSER_RUNTIME_PUBLIC_BASE_URL` 留空，Runtime 返回同源 `/vnc/...` 地址；如由外部反向代理承载该路径，再将其设置为受保护的公开基础地址。

Runtime 镜像包含 Chromium、Xvfb、Fluxbox 和 x11vnc。构建阶段只从 Debian `novnc` 包提取 noVNC 静态资源，最终镜像不保留其 Python/websockify 运行依赖；WebSocket 到本地 RFB 的桥接由 Runtime 的 Node 服务提供。

`data/workflows` 对应的运行期目录为 `/app/data/workflows`，只通过外部 Docker 卷持久化，不复制进镜像。
