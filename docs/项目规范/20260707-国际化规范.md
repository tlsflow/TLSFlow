# GCAC 前端国际化（i18n）规范

> 版本：1.0 | 更新日期：2026-07-07 | 适用范围：`web/src/` 所有前端代码

---

## 一、概述

GCAC 前端使用 `vue-i18n`（Composition API 模式）实现国际化，支持 8 种语言。所有面向用户的文案必须通过 i18n 系统输出，**禁止**在组件或 TypeScript 文件中硬编码任何中文、英文或其他语言字符串。

### 1.1 支持的语言

| 代码 | 语言 | 默认语言 |
|---|---|---|
| `zh-CN` | 简体中文 | ✅ |
| `zh-TW` | 繁體中文 | |
| `en-US` | English | |
| `ja-JP` | 日本語 | |
| `fr-FR` | Français | |
| `ru-RU` | Русский | |
| `pt-BR` | Português (Brasil) | |
| `ko-KR` | 한국어 | |

### 1.2 架构

```
web/src/i18n/
├── index.ts          # i18n 实例创建、setI18nLocale() 懒加载
├── locales.ts        # 支持的语言列表、标签、类型定义
├── zh-CN.ts          # 简体中文（默认语言，也是开发时的主要编辑目标）
├── zh-TW.ts          # 繁體中文
├── en-US.ts          # English
├── ja-JP.ts          # 日本語
├── fr-FR.ts          # Français
├── ru-RU.ts          # Русский
├── pt-BR.ts          # Português (Brasil)
├── ko-KR.ts          # 한국어
└── extract-locales.ts # 语言文件提取脚本（从 messages.ts 生成各语言文件）
```

- **默认语言 `zh-CN`** 在应用启动时静态导入，立即可用。
- **其他 7 种语言**通过 `import()` 动态懒加载，首次切换时才加载对应语言文件。
- **`zh-CN.ts` 是开发时的主编辑目标**：新增 key 先加入 zh-CN.ts，再同步到其余语言文件。

## 二、Key 命名规范

### 2.1 层次结构

翻译 key 采用**点号分隔的嵌套对象层级**，顶层按业务领域划分：

```
app.*           应用级通用（品牌名、平台描述）
common.*        全局通用文案（刷新、退出、加载中等）
api.*           API 调用相关（错误提示等）
auth.*          认证相关（登录、密码等）
designSystem.*  设计系统组件文案（status、risk、confirm 等）
shell.*         壳布局（面包屑、导航、用户菜单等）
preferences.*   偏好设置（主题、语言切换等）
nav.*           导航菜单
routes.*        路由标签
businessPage.*  通用业务页面框架
executionDetail.* 执行详情
executions.*    执行记录
plugins.*       插件管理
deploymentPlans.* 部署计划
agents.*        应用资产（Agent）
dashboard.*     仪表盘
gateways.*      网关管理
audit.* / auditFormat.*  审计日志
securityAdmin.* 安全管理
settings.*      系统设置
bindings.*      证书绑定
assets.*        资产管理
certificates.*  证书管理
workflows.*     工作流
monitoring.*    监控告警
login.*         登录页
errors.*        全局错误页（403/404）
```

### 2.2 领域内标准结构

每个业务领域内部推荐遵循以下标准键结构：

```typescript
{domain}: {
  title:              // 页面/区块标题
  description:        // 页面/区块描述（长文本）
  resourceName:       // 资源的人类可读名称

  // 标准子节点（按需选用）：
  actions: {          // 操作按钮文案
    create: '...',
    delete: '...',
    edit: '...',
  },
  columns: {          // 表格列头
    name: '...',
    status: '...',
    createdAt: '...',
  },
  fields: {           // 表单字段标签
    name: '...',
    description: '...',
  },
  errors: {           // 错误消息
    loadFailed: '...',
    createFailed: '...',
    deleteFailed: '...',
  },
  empty: {            // 空状态
    title: '...',
    description: '...',
  },
  feedback: {         // 操作反馈（成功/失败提示）
    createSuccess: '...',
    deleteSuccess: '...',
  },
  placeholders: {     // 输入框占位符
    name: '...',
  },
  tabs: {             // 标签页名称
    overview: '...',
    settings: '...',
  },
  status: {           // 状态值
    DRAFT: '...',
    PUBLISHED: '...',
  },
  hints: {            // 帮助提示文本
    name: '...',
  },
  metrics: {          // 指标卡片
    total: {
      title: '...',
      description: '...',
    }
  },
  detail: {           // 详情面板/弹窗
    title: '...',
    titleWithName: '{name} 详情',
  },
}
```

### 2.3 命名风格

| 场景 | 风格 | 示例 |
|---|---|---|
| 普通键 | `camelCase` | `defaultBreadcrumb`、`requestFailed` |
| 状态值键 | `UPPER_CASE` | `DRAFT`、`PUBLISHED`、`RUNNING` |
| 枚举值 | `UPPER_SNAKE_CASE`（仅在值对象中） | `risk.LOW.label` |
| 短标签 | `camelCase` 无分隔符 | `userFallback`、`closeAria` |

### 2.4 文案风格

- **中文为主**（`zh-CN`），其他语言由中文语义翻译，不得产生偏离原意的翻译。
- 专业产品语调：企业级 SSL 证书管理 / 自动化部署平台，文案应正式、精准。
- 按钮文字简洁（2-4 字为宜）。
- 空状态 / 错误提示应当明确告知用户发生了什么、可采取什么操作。
- 不得出现调试类/口语化文案（如"前端骨架用户"、"兜底中"、"已拿到"等）。

## 三、插值语法

### 3.1 标准插值

使用 `{paramName}` 语法：

```typescript
// zh-CN.ts 中定义
title: '确认{action}',
impactCount: '影响资源数量：{count}',
stepsCompleted: '{completed}/{total} 步骤已完成',

// 使用时
t('designSystem.confirm.title', { action: '删除' })
t('designSystem.confirm.impactCount', { count: selectedItems.length })
```

### 3.2 参数类型

参数统一为 `string | number` 类型：

```typescript
type I18nParams = Record<string, string | number>
type I18nTranslate = (key: string, params?: I18nParams) => string
```

### 3.3 约束

- **不修改插值变量名**：`{name}`、`{count}` 等占位符在所有语言中保持原样。
- **不使用 Vue I18n 内置复数**（`$tc`、`{n}` 复数规则），多语言计数逻辑由 JS 层处理后再传入翻译。
- **不使用 `@:linked` 消息引用**（链接消息语法），当前项目未启用此特性。

## 四、使用方式

### 4.1 Vue SFC 中（推荐方式）

**Composition API — `useI18n()`：**

```typescript
<script setup lang="ts">
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
</script>

<template>
  <!-- 简单文案 -->
  <h1>{{ t('agents.title') }}</h1>

  <!-- 带插值 -->
  <span>{{ t('workflows.templates.detail.titleWithName', { name: rowName }) }}</span>

  <!-- ARIA 标签 -->
  <button :aria-label="t('designSystem.dryRunChecklist.ariaLabel')">
    {{ t('common.refresh') }}
  </button>
</template>
```

**全局注入 `$t`**（因 `globalInjection: true` 已开启，模板中也可用 `$t`，但项目中统一使用 Composition API 的 `t`）。

### 4.2 TypeScript 文件中（非 Vue 组件）

在 `.ts` 文件中，直接导入 `i18n` 实例，使用 `i18n.global.t()`：

```typescript
import { i18n } from '@/i18n'

// 简单文案
const label = i18n.global.t('common.refresh')

// 带参数
const msg = i18n.global.t('api.errors.requestFailed', { message: error.message })

// 带默认参数处理
function defaultT(key: string, params?: Record<string, string | number>): string {
  return i18n.global.t(key, params ?? {})
}
```

**使用场景：**
- `api/client.ts` — API 错误消息
- `router/guards.ts` — 页面标题、面包屑导航
- `stores/*.ts` — Store 中的错误提示
- `providers/*.ts` — 认证/权限消息
- `composables/useBusinessPage.ts` — 通用页面框架
- `views/**/*.ts` — 视图辅助逻辑（表单校验、导出文件名等）

### 4.3 前缀包装器模式

当同一文件中频繁使用某个领域下的 key 时，可以创建带前缀的包装函数，减少重复：

```typescript
// 证书详情面板
function detailPanelT(key: string, named?: Record<string, unknown>) {
  const fullKey = `certificates.detailPanel.${key}`
  return named ? t(fullKey, named) : t(fullKey)
}

// 工作流画布模型
function canvasModelText(key: string, params?: Record<string, string | number>): string {
  const fullKey = `workflows.canvasModel.${key}`
  return params ? i18n.global.t(fullKey, params) : i18n.global.t(fullKey)
}
```

### 4.4 动态 key 构造

当 key 需要动态拼接时，使用 `te()` 检查 key 是否存在：

```typescript
// 仪表盘动态指标
function dashboardText(key: string, fallback: string, params?: Record<string, unknown>): string {
  return te(key) ? t(key, params ?? {}) : fallback
}

// 使用
dashboardText(`dashboard.metrics.${metric.key}.title`, metric.title)
```

### 4.5 回退包装器

```typescript
// 当翻译不存在时，显示 fallback 文本
function translateWithFallback(
  t: I18nTranslate | undefined,
  key: string,
  fallback: string,
  params?: I18nParams
): string {
  const translate = t ?? ((messageKey, params) => i18n.global.t(messageKey, params ?? {}))
  const translated = translate(key, params)
  if (translated && translated !== key) return translated
  return formatI18nFallback(fallback, params)
}
```

## 五、ARIA 无障碍标签

ARIA 标签也必须走 i18n，命名约定：

- 优先使用 `{domain}.aria.{key}` 结构：
  ```typescript
  designSystem.executionProgress.aria.progressOverview
  ```

- 无 aria 子对象时，可用 `{key}Aria` 后缀：
  ```typescript
  businessPage.metricsAria
  businessPage.resourceActionsAria
  ```

## 六、新增翻译 Key 的工作流

1. **先在 `zh-CN.ts` 中添加新 key**，遵循上述命名规范和层级结构。
2. **在 `en-US.ts` 中添加对应的英文翻译**。
3. **在其余 6 个语言文件中添加对应翻译**（`zh-TW`、`ja-JP`、`fr-FR`、`ru-RU`、`pt-BR`、`ko-KR`）。如果暂无翻译能力，可以暂时使用英文值作为 fallback，**但 key 本身必须存在**，否则运行时 `t()` 会返回 key 字符串本身。
4. **在代码中使用 `t('your.new.key')` 引用**，不要硬编码文案。

### 6.1 语言文件格式

每个语言文件是 TypeScript 模块：

```typescript
// GCAC i18n locale file — edit directly.
// When adding new keys: add to zh-CN.ts first, then propagate to other locale files.
export default {
  app: {
    brand: 'GCAC 控制台',
    platform: '企业 SSL 证书生命周期管理平台',
    // ...
  },
  // ... 其余 29 个顶层 section
} as const
```

**注意**：`as const` 是 TypeScript 类型断言，必须保留在文件末尾。

## 七、禁止事项

- ❌ 在 `.vue` 模板中硬编码中文/英文/日文等自然语言文字
- ❌ 在 `.ts` 文件中返回硬编码的自然语言字符串作为 UI 展示文本
- ❌ 使用 `{{ $t(key) || '硬编码fallback' }}` — fallback 也必须走 i18n key
- ❌ 新建 i18n key 时仅添加到 `zh-CN.ts` 而忽略其他语言文件
- ❌ 在翻译中使用调试类/口语化文案
- ❌ 在翻译 value 中嵌入 HTML 标签（使用 Vue I18n 的 `v-html` 有 XSS 风险；如需富文本，应在组件中拆分 slot 或用 `t()` 分别翻译各段）
- ❌ 在 key 名称中使用中文或特殊字符

## 八、检查清单

新增或修改前端文案时，确认以下事项：

- [ ] 所有面向用户的字符串均通过 `t()` 或 `i18n.global.t()` 输出
- [ ] 新 key 已添加到 `zh-CN.ts`（并遵循 `{domain}.{category}.{key}` 层级）
- [ ] 新 key 已同步添加到其余 7 个语言文件（至少包含英文 fallback）
- [ ] ARIA 标签也走 i18n
- [ ] 插值变量名在所有语言中保持一致
- [ ] 无硬编码 fallback 字符串（如 `t(key) || '加载失败'`）
- [ ] `vue-tsc --noEmit` 通过
- [ ] `vite build` 通过
