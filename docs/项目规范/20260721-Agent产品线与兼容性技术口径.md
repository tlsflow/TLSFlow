# Agent 产品线与兼容性技术口径

状态：生效

生效日期：2026-07-21

## 1. 文档定位

本文是 GCAC 关于 Agent 产品线、操作系统支持基线、兼容性扩展、Provider/Adapter/Executor 边界和支持等级的项目级唯一技术口径。

当历史 Spec、补充文档、代码注释或示例与本文冲突时，以本文、`018.1-能力驱动的证书部署适配器与兼容性目录` 和 `018.2-LinuxAgent产品线与能力适配架构` 为准。冲突文档必须在后续任务中修订，不得继续按旧口径实现。

## 2. 统一架构原则

1. 统一的是控制面协议、Action Contract、Capability、Operation、结果、错误和恢复语义，不要求所有 Agent 使用同一种语言或同一个二进制。
2. 兼容性由 Fact、Capability、Adapter Manifest、Adapter Resolver 和 Compatibility Profile 决定。
3. 禁止通过新增操作系统、发行版、产品版本或执行通道 `if/else`、`switch` 扩展兼容性。
4. Product Adapter、Certificate Store、Artifact Codec、Service Controller、Privilege Adapter、Transport Adapter 和 Verifier 必须职责分离。
5. 未找到唯一 Handler、Adapter 或 Executor 时失败关闭，禁止默认实现和伪成功。
6. 支持等级由测试证据决定，兼容性矩阵必须从 Profile 自动生成。

## 3. Agent 产品线

### 3.1 Windows Compatibility Agent

- 支持范围：Windows Server 2008 R2 SP1、Windows Server 2012、Windows Server 2012 R2。
- Runtime：C# / .NET Framework 4.8。
- 定位：正式受控兼容产品线，不复制 Modern Agent 的全部能力。
- 安装前置：SP、.NET Framework 4.8、TLS 1.2、必要补丁、权限和网络检查。
- 扩展方式：静态 Action Handler Registry 和 Adapter Registry。

### 3.2 Windows Modern Agent

- 支持范围：Windows Server 2016 及以上。
- Runtime：Go 当前项目批准的受支持版本。
- 定位：Windows 长期演进的现代正式产品线。
- 不得为了旧 Windows 降低 Go 工具链、依赖或控制面 TLS 基线。

### 3.3 Linux Go Full Agent

- 只维护一条正式 Linux Agent 产品线。
- Runtime：Go 当前项目批准的受支持版本，默认 `CGO_ENABLED=0`。
- 初始最低规划基线：Linux Kernel 3.2 及以上；最终要求取当前 Go 工具链和 GCAC 实际系统调用要求中的较高者。
- 首批构建架构：`linux/amd64`、`linux/arm64`。
- 发行版名称只用于认证和展示，不用于执行策略。
- 低于运行基线或架构不受支持时，不提供旧 Linux Agent。

### 3.4 Gateway Agent

- Gateway Agent 负责隔离区路由、转发、区域探测和受控代理。
- Gateway 不改变目标产品语义，不替代 Product Adapter。
- Gateway 可以承载 SSH、WinRM/WMI/SMB、HTTP 或下游 Agent 转发。

### 3.5 已废弃产品概念

- “Windows PowerShell Full Agent 作为正式产品线”已废弃。
- “所有平台统一使用唯一 Go Runtime”已废弃。
- “Windows Server 2003/2008 非 R2 Legacy Agent”已废弃。
- “旧 Linux Go Agent/冻结旧 Go 工具链”已废弃。
- `windows-powershell-full-agent` 目录只能作为历史兼容入口或安装代理存在，不代表正式 Runtime。

## 4. 操作系统支持范围

### 4.1 Windows

| 操作系统 | Agent 支持 | 自动部署定位 |
| --- | --- | --- |
| Windows Server 2003 / 2003 R2 | 不支持 | 仅资产记录、迁移建议或显式人工流程 |
| Windows Server 2008 非 R2 | 不支持 | 仅资产记录、迁移建议或显式人工流程 |
| Windows Server 2008 R2 SP1 | Compatibility Agent | 需通过前置检查和 Profile 认证 |
| Windows Server 2012 / 2012 R2 | Compatibility Agent | 需通过 Profile 认证 |
| Windows Server 2016+ | Modern Agent | 正式现代产品线 |

`unsupported` 目标不得生成 Agent 安装计划，也不得通过普通审批绕过为自动部署。

### 4.2 Linux

Linux 不维护发行版白名单作为执行逻辑。支持判断至少包含：

- Kernel Runtime Baseline；
- CPU Architecture；
- init system；
- Privilege；
- Filesystem/mount；
- SELinux/AppArmor；
- 产品和证书格式；
- Adapter 和测试证据。

已认证发行版只能证明对应能力组合通过测试，不代表同系列所有版本自动 certified。

## 5. Provider、Adapter 与 Executor 边界

### Provider

- 负责发现产品领域事实和生成领域操作意图。
- 不负责根据 OS/发行版生成命令。
- 不直接执行 SSH、CURL、WinRM、systemd、SCM 或 sudo。

### Adapter

- 把独立平台或产品职责转换为 Typed Operation。
- 通过 Manifest 注册并声明 Capability Requirement。
- 新增兼容性优先新增 Adapter/Profile，不修改 Resolver。

### Executor / Transport

- 负责本地或远程安全执行。
- 不重新解释产品领域语义。
- 未注册类型必须返回错误，禁止 planned success。

## 6. Legacy 与降级模式

`013-Legacy Agent与脚本包模式` 中的“Legacy Agent”概念自 2026-07-21 起不再代表新的长期 Agent 产品线。

降级通道统一为：

- Gateway；
- SSH/SFTP/SCP；
- WinRM/WMI/SMB；
- CURL/HTTP；
- 签名脚本包；
- 人工确认；
- 仅监控和资产记录。

降级通道是否可执行仍由 Capability、Profile、审批和风险策略决定，不得因为目标老旧自动放宽安全要求。

## 7. 支持等级

- `certified`：固定真实环境完成完整成功、失败、回滚、恢复和安全测试。
- `supported`：有正式实现和主要真实环境测试。
- `compatible`：Capability 完全匹配，但目标环境未直接认证。
- `experimental`：实现和 fixture 可用，真实验证有限。
- `legacy`：仅远程、脚本包或人工辅助，不安装正式 Agent。
- `unsupported`：禁止自动执行和 Agent 安装。
