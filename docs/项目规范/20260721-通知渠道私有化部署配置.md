# 通知渠道私有化部署配置

## 适用范围

GCAC 支持企业微信、飞书和钉钉机器人通知连接到大型企业的私有化或专有部署实例。私有化实例没有可由 GCAC 统一硬编码的公共域名，因此必须由平台运维人员显式批准实例的 HTTPS Origin。

渠道管理员只能填写 Webhook URL，不能自行关闭 SSRF 防护或授权任意内网地址。

## 环境变量

以下变量均为逗号分隔的精确 HTTPS Origin，不允许包含路径、查询参数、Fragment 或用户信息：

```text
GCAC_NOTIFICATION_WECOM_PRIVATE_ORIGINS=https://wecom.example.internal,https://wecom-dr.example.internal:8443
GCAC_NOTIFICATION_FEISHU_PRIVATE_ORIGINS=https://feishu.example.internal
GCAC_NOTIFICATION_DINGTALK_PRIVATE_ORIGINS=https://dingtalk.example.internal
```

Origin 包含协议、主机和可选端口。配置 `https://wecom.example.internal` 不会授权其他子域名，也不会授权 `http://wecom.example.internal` 或不同端口。

修改环境变量后需要重启 GCAC 后端进程才能稳定生效。

## 企业 CA

私有化实例如果使用企业内部 CA 签发的 TLS 证书，应通过 Node.js 标准环境变量配置额外 CA：

```text
NODE_EXTRA_CA_CERTS=C:\gcac\certs\enterprise-root-ca.pem
```

Linux 示例：

```text
NODE_EXTRA_CA_CERTS=/etc/gcac/certs/enterprise-root-ca.pem
```

GCAC 不提供关闭 TLS 证书校验的渠道选项。跳过证书校验会使 Webhook Token、签名密钥和通知内容暴露给中间人攻击，不符合生产安全要求。

## 安全边界

- 公有云地址继续使用平台内置官方域名和路径校验。
- 私有化地址必须匹配对应平台的精确 HTTPS Origin 白名单。
- 只有已批准 Origin 才允许解析到 RFC1918 IPv4 私网或 IPv6 ULA 地址。
- 回环、链路本地、云元数据、共享地址空间、组播和保留地址始终禁止。
- DNS 解析结果在连接阶段必须与预检查结果一致，防止 DNS 重绑定。
- 重定向只能停留在同一 Origin，不能切换主机、协议或端口。
- Webhook URL 和平台 Secret 仍只保存为 SecretRef，不写入渠道表明文。

## 配置步骤

1. 由企业平台管理员确认私有化实例的机器人 Webhook URL 和 TLS 证书链。
2. 由 GCAC 运维提取 URL 的 Origin，加入对应平台环境变量。
3. 如使用企业 CA，配置 `NODE_EXTRA_CA_CERTS` 并重启后端。
4. 在“通知管理”中选择对应平台和“私有化部署”。
5. 输入完整 Webhook URL 和可选签名密钥，保存为停用渠道。
6. 执行测试发送，确认渠道健康、延迟和失败分类正确后再启用。
