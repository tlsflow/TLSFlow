# 插件 Logo 资源与展示规范

> 版本：1.0 | 更新日期：2026-08-22
> 适用范围：统一插件 Manifest、工作流模板元数据，以及 Web 端所有插件/平台 Logo 展示。

## 一、结论

Manifest 只负责声明 Logo 资源地址，不负责声明显示尺寸。`logoUrl` 是 72 × 48 横向资源，`logoSquareUrl` 是 72 × 72 方形资源；显示尺寸由 GCAC 宿主统一决定，插件作者不得在 Manifest、工作流 DSL 或资源文件中写入页面尺寸。

Logo 的展示必须使用设计系统组件 `GcPluginLogo`。组件统一处理同源地址校验、加载失败回退、`contain` 缩放和固定展示槽位，禁止各业务页面重新实现一套 Logo 加载逻辑。

## 二、资源要求

1. 首选 SVG：必须包含 `viewBox`，不得依赖外部图片、外部字体、脚本或动画；图形应在画布中央保留安全边距。
2. 使用位图时，推荐提供透明背景 PNG，源文件不低于 512 × 512 像素；不得提交只适合某一个页面截图的裁剪图。
3. 同一 Logo 可以是方形图标或横向字标。宿主统一使用 `object-fit: contain`，不得裁切或拉伸横向字标。
4. 内置插件使用前端静态资源路径。资源统一放在 `web/public/plugin-logos/`，Manifest 使用浏览器路径 `/plugin-logos/<plugin-slug>.svg` 和 `/plugin-logos/<plugin-slug>-square.svg`。插件版本发布后，已使用的 Logo 文件和地址不可原地替换。
5. Manifest 和工作流 Schema 目前仍接受 HTTP(S) 地址以保持合同兼容，但 Web 展示只加载当前 GCAC 同源资源。跨域地址会被安全回退为插件首字母，不应作为正式交付资源。
6. 用户插件包内的 `backend/src/...`、`data/...` 或其他服务器磁盘路径不是浏览器 URL。用户插件必须先把资源发布到宿主登记的同源静态地址，再在 Manifest 中填写该 URL；当前没有静态发布机制时，宿主只能显示首字母回退。
7. 已发布插件的 Manifest 和 Logo 资源不可原地改写；为现有插件补充 `logoSquareUrl` 时，必须递增插件版本并重新生成摘要。未声明该字段的旧版本继续回退使用 `logoUrl`。

## 三、固定展示尺寸

### 资源文件和命名

```text
web/public/plugin-logos/<plugin-slug>.<ext>          # 72 × 48 横向 Logo，Manifest.logoUrl
web/public/plugin-logos/<plugin-slug>-square.<ext>   # 72 × 72 方形 Logo，Manifest.logoSquareUrl
```

`<plugin-slug>` 使用插件稳定标识的短横线形式，只允许小写英文字母、数字和短横线；`<ext>` 推荐使用 `svg`，也可使用透明 `png`。例如 `citrix-adc.svg` 与 `citrix-adc-square.svg`。这里的 72 × 48、72 × 72 是资源变体的设计画布比例；SVG 以 `viewBox` 保持比例即可，PNG 若用于高 DPI 屏幕应提供更高像素密度但保持同一比例。不需要提供 `48 × 48` 文件；接入向导把方形资源放入 48 × 48 槽位，由 `contain` 自动缩放。旧插件没有 `logoSquareUrl` 时，详情和向导回退使用 `logoUrl`。

Manifest 示例：

```json
{
  "logoUrl": "/plugin-logos/citrix-adc.svg",
  "logoSquareUrl": "/plugin-logos/citrix-adc-square.svg"
}
```

下表是 Logo 外框尺寸，不是源文件尺寸。源图始终在外框内完整显示，外框尺寸不会因 Logo 是否存在或源图宽高比变化。

| 使用场景 | 设计系统尺寸令牌 | 外框尺寸 | 说明 |
| --- | --- | --- | --- |
| 插件市场卡片 | `--gc-size-plugin-logo-market-inline` / `--gc-size-plugin-logo-market-block` | 72 × 48 px | 适合卡片头部横向布局，方形图标和横向字标均使用 contain |
| 插件详情弹窗 | `--gc-size-plugin-logo-detail` | 72 × 72 px | 详情身份区使用方形稳定槽位 |
| 应用资产接入向导 | `--gc-size-plugin-logo-onboarding` | 48 × 48 px | 平台选择卡片 |
| 设备接入向导 | `--gc-size-plugin-logo-onboarding` | 48 × 48 px | 平台选择卡片，横向 Logo 不再按高度铺满后裁切 |

无 Logo、地址不安全或图片加载失败时，仍使用相同外框尺寸显示首字母回退，不能改变卡片布局。

## 四、调用规则

- `GcPluginLogo` 是唯一的 Logo 展示入口，调用方传入 `logoUrl`、可选的 `squareLogoUrl`、已翻译的 `alt` 文案、回退文字和尺寸档位。
- 组件只允许同源 Web 路径，拒绝 `file:`、`data:`、协议相对跨域地址和其他外部来源；加载失败只影响当前组件实例。
- 插件市场使用 `logoUrl`；详情弹窗、应用资产接入和设备接入优先使用 `logoSquareUrl`，缺失时回退到 `logoUrl`。这些字段都应由后端平台投影透传，设备向导仍可额外使用宿主内置的 Windows/Linux 静态 Logo 映射。
- 页面不得直接写 Logo 的 `width`、`height`、`object-fit` 或重复的 URL 解析逻辑；尺寸必须由 `--gc-size-plugin-logo-*` 令牌提供。
- Logo 变更属于插件资源变更，必须递增插件版本并重新生成包摘要，不能直接覆盖已发布版本的资源。

## 五、验收清单

- [ ] Manifest 中的 `logoUrl` 和可选 `logoSquareUrl` 是浏览器可访问的同源静态资源路径。
- [ ] SVG/PNG 在 72 × 48、72 × 72 和 48 × 48 三种外框中均完整可见，没有裁切、拉伸或布局跳变。
- [ ] 删除 Logo、使用非法地址和模拟图片加载失败时，首字母回退仍保持对应外框尺寸。
- [ ] 四个使用场景均通过 `GcPluginLogo`，没有页面私有 Logo 解析函数。
- [ ] Logo 修改已递增插件版本，并绑定新的 `packageHash`、`manifestHash` 和 `resourceHash` 验收记录。
