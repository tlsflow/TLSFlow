# 插件 Logo 资源与展示规范

> 版本：1.0 | 更新日期：2026-08-22
> 适用范围：统一插件 Manifest、工作流模板元数据，以及 Web 端所有插件/平台 Logo 展示。

## 一、结论

`logoUrl` 只负责声明 Logo 资源地址，不负责声明显示尺寸。显示尺寸由 GCAC 宿主统一决定，插件作者不得在 Manifest、工作流 DSL 或资源文件中写入页面尺寸。

Logo 的展示必须使用设计系统组件 `GcPluginLogo`。组件统一处理同源地址校验、加载失败回退、`contain` 缩放和固定展示槽位，禁止各业务页面重新实现一套 Logo 加载逻辑。

## 二、资源要求

1. 首选 SVG：必须包含 `viewBox`，不得依赖外部图片、外部字体、脚本或动画；图形应在画布中央保留安全边距。
2. 使用位图时，推荐提供透明背景 PNG，源文件不低于 512 × 512 像素；不得提交只适合某一个页面截图的裁剪图。
3. 同一 Logo 可以是方形图标或横向字标。宿主统一使用 `object-fit: contain`，不得裁切或拉伸横向字标。
4. 内置插件使用前端静态资源路径，例如 `/plugin-logos/<canonical-name>.svg`；插件版本发布后，已使用的 Logo 文件和地址不可原地替换。
5. Manifest 和工作流 Schema 目前仍接受 HTTP(S) 地址以保持合同兼容，但 Web 展示只加载当前 GCAC 同源资源。跨域地址会被安全回退为插件首字母，不应作为正式交付资源。

## 三、固定展示尺寸

下表是 Logo 外框尺寸，不是源文件尺寸。源图始终在外框内完整显示，外框尺寸不会因 Logo 是否存在或源图宽高比变化。

| 使用场景 | 设计系统尺寸令牌 | 外框尺寸 | 说明 |
| --- | --- | --- | --- |
| 插件市场卡片 | `--gc-size-plugin-logo-market-inline` / `--gc-size-plugin-logo-market-block` | 72 × 48 px | 适合卡片头部横向布局，方形图标和横向字标均使用 contain |
| 插件详情弹窗 | `--gc-size-plugin-logo-detail` | 72 × 72 px | 详情身份区使用方形稳定槽位 |
| 应用资产接入向导 | `--gc-size-plugin-logo-onboarding` | 48 × 48 px | 平台选择卡片 |
| 设备接入向导 | `--gc-size-plugin-logo-onboarding` | 48 × 48 px | 平台选择卡片，横向 Logo 不再按高度铺满后裁切 |

无 Logo、地址不安全或图片加载失败时，仍使用相同外框尺寸显示首字母回退，不能改变卡片布局。

## 四、调用规则

- `GcPluginLogo` 是唯一的 Logo 展示入口，调用方传入 `logoUrl`、已翻译的 `alt` 文案、回退文字和尺寸档位。
- 组件只允许同源 Web 路径，拒绝 `file:`、`data:`、协议相对跨域地址和其他外部来源；加载失败只影响当前组件实例。
- 插件市场和详情弹窗使用插件 Manifest 的 `logoUrl`；应用资产接入和设备接入使用后端平台投影的 `logoUrl`，设备向导可额外使用宿主内置的 Windows/Linux 静态 Logo 映射。
- 页面不得直接写 Logo 的 `width`、`height`、`object-fit` 或重复的 URL 解析逻辑；尺寸必须由 `--gc-size-plugin-logo-*` 令牌提供。
- Logo 变更属于插件资源变更，必须递增插件版本并重新生成包摘要，不能直接覆盖已发布版本的资源。

## 五、验收清单

- [ ] Manifest 或工作流中的 `logoUrl` 是浏览器可访问的同源静态资源路径。
- [ ] SVG/PNG 在 72 × 48、72 × 72 和 48 × 48 三种外框中均完整可见，没有裁切、拉伸或布局跳变。
- [ ] 删除 Logo、使用非法地址和模拟图片加载失败时，首字母回退仍保持对应外框尺寸。
- [ ] 四个使用场景均通过 `GcPluginLogo`，没有页面私有 Logo 解析函数。
- [ ] Logo 修改已递增插件版本，并绑定新的 `packageHash`、`manifestHash` 和 `resourceHash` 验收记录。
