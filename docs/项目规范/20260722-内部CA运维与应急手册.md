# 内部 CA 运维与应急手册

## 1. 架构边界

- 应用证书 CA 与 Agent 身份认证 CA 必须隔离，禁止复用根证书、签发密钥和 Profile。
- 推荐采用“离线根 CA + 在线中间 CA”；“仅根 CA”仅适用于明确接受根密钥在线风险的小规模环境。
- GCAC 内置 CA 适合快速落地；独立 Windows/Linux CA Node 适合需要隔离部署、冗余或硬件密钥的环境；Microsoft AD CS、ACME、EST、SCEP 通过 Provider 适配器接入。
- CA 拓扑、部署模式、运行平台、可用性和密钥后端是五个独立维度，不得用“Windows CA”或“Linux CA”代替协议和密钥能力描述。

## 2. 密钥托管

- Windows Full Agent 使用 CNG/KSP 创建 `Exportable=FALSE` 的机器密钥，控制面只接收 CSR、公钥指纹和不透明 `localKeyRef`。
- Linux Full Agent 当前使用权限为 `0600` 的文件密钥，必须标记为 `exportable/software_controlled`，不得伪装成不可导出；后续可接入 TPM 或 PKCS#11。
- 网络设备和嵌入式设备由 GCAC 为每个应用资产生成独立密钥，通过 SecretRef 管理和部署，禁止跨应用资产复用同一私钥。
- 软件密钥不论是否经过加密保存，都不能标记为不可导出。

## 3. 日常操作

1. 创建 CA Provider，确认部署模式、平台、可用性和能力探测结果。
2. 在创建 CA 前执行风险预览，保存用户选择和确认令牌。
3. 创建安全域对应的证书 Profile，限制 DNS 后缀、有效期、通配符、算法、审批和续期策略。
4. 对有 Agent 的应用资产调用 `certificate.key.create_csr`，对无 Agent 资产使用托管密钥申请。
5. 签发后调用 `certificate.install_issued`，必须先验证证书公钥与本地密钥匹配。
6. 续期默认换钥；本地持钥进入 `key_pending`，托管密钥可自动创建新申请。
7. 吊销和信任分发必须经过高风险审批，并记录 CRL、OCSP 能力缺口。
8. Linux 信任分发使用 `certificate.trust.install` 原子写入并保留备份，失败或迁移结束时调用 `certificate.trust.rollback`；Windows 使用同名动作写入本机 Root 存储并按拇指纹回滚。

## 4. 风险治理

- 报表分别检测“同证书指纹跨应用资产”和“同公钥指纹跨应用资产”。
- 同一逻辑应用的冗余实例降级为警告，但仍提示故障域集中。
- 通配符证书跨安全域复用升级为严重风险。
- 整改预览必须为每个应用资产生成独立换钥申请，分批部署、验证，再吊销共享证书。

## 5. CA 密钥疑似泄露

1. 立即将 CA 状态标记为 `compromised`，停止签发和续期。
2. 禁用相关 Provider、CA Node 身份和任务租约，保存审计证据。
3. 盘点该 CA 的全部签发证书、绑定、信任分发范围和备份位置。
4. 创建新密钥和新 CA 链；根密钥泄露时必须重建对应信任域，中间 CA 泄露时至少更换中间 CA 和其签发证书。
5. 批量创建独立换钥申请，按安全域和业务优先级分批部署。
6. 发布 CRL、更新 OCSP 或执行 Provider 对应吊销流程；不支持自动发布时必须产生显式告警和人工步骤。
7. 验证全部入口和后端信任后，退役旧密钥、旧证书链和旧信任锚。

## 6. 备份与恢复

- 根 CA 私钥备份必须离线、加密、双人授权，并定期做恢复演练。
- 中间 CA 和 CA Node 的备份应包含配置、证书链、密钥后端引用和幂等签发记录，不应导出硬件保护私钥。
- 恢复后先校验 CA 指纹、链路和节点身份，再开放签发。
- 双节点恢复时先启用一个活动节点，确认租约和心跳正常后再启用备用节点，避免双主签发。
- `active_active` 仅允许中间 CA 配合 HSM、KMS 或 PKCS#11 等共享安全密钥后端；文件密钥和在线根 CA 不得配置多活。

## 7. 外部 CA 接入

- Microsoft AD CS、ACME、EST、SCEP 必须分别配置协议适配器，不得把不同协议伪装成同一个通用“Linux CA”接口。
- Provider 凭据只保存 SecretRef，连接测试、错误日志和审计不得输出令牌、PIN、密码或认证头。
- 远程签发返回 `pending` 或 `unknown` 时保留 Provider Request ID，通过查询动作恢复状态，不得直接重复签发。
- Provider 不支持吊销、CRL 或 OCSP 时必须显示能力缺口，禁止伪造成功结果。

## 8. 验证清单

- CA API 和 OpenAPI 不暴露私钥、明文 Secret 或 `privateKeySecretRef`。
- Windows 本地密钥证据包含 CNG Provider、MachineKeySet 和 `Exportable=FALSE`。
- Linux 文件密钥权限为 `0600`，返回值明确标记可导出。
- 证书安装前完成公钥匹配校验。
- 注册令牌不能重放，活动节点冲突会被拒绝。
- 续期任务按证书版本和续期窗口去重。
- 吊销、信任分发和高风险整改使用匹配审批单。
- 前端所有时间转换为浏览器本地时间，所有用户文案来自 i18n。
- 工作流 DSL 未因本功能新增步骤类型、变量或 SecretRef 规则；主题系统未新增 Token 或设计系统组件，现有规范无需同步修改。
