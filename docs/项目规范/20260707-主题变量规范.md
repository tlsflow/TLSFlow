# GCAC 前端主题变量规范

> 版本：1.6 | 更新日期：2026-08-22 | 适用范围：`web/src/` 所有前端代码

---

## 一、概述

GCAC 前端采用**语义化 CSS 自定义属性（CSS Custom Properties）**作为唯一的设计令牌系统，实现亮色/暗色双主题无缝切换。工作台页面的具体视觉语言由 `001.3.1-控制台工作台视觉重构与主题适配` 维护，本文件负责令牌、主题切换和组件消费规则。

- **不使用** Tailwind CSS、UnoCSS 或任何原子化 CSS 框架。
- **不使用** CSS-in-JS 方案。
- **所有设计令牌**统一定义在 `web/src/design-system/tokens/index.css`，全项目仅此一处来源。

主题切换通过 `<html>` 元素的 `data-theme` 属性驱动：移除或设置 `data-theme="light"` 为亮色、`data-theme="dark"` 为暗色。

## 二、CSS 变量命名规范

### 2.1 命名格式

```
--gc-{类别}-{属性}[-{修饰符}]
```

| 部分 | 说明 |
|---|---|
| `gc` | 项目固定前缀 |
| `{类别}` | 取值：`color`、`space`、`font`、`radius`、`shadow`、`gradient` |
| `{属性}` | 语义化属性名，如 `bg`、`text`、`border`、`primary`、`surface` |
| `{修饰符}` | 可选，进一步细分，如 `strong`、`muted`、`soft`、`hover`、`sm` |

### 2.2 已定义令牌类别

#### 颜色 (`--gc-color-*`)

按**语义角色**命名，而非按色值命名：

| 语义组 | 变量示例 | 说明 |
|---|---|---|
| 背景 | `--gc-color-bg`、`--gc-color-bg-strong` | 页面底色 |
| 表面 | `--gc-color-surface`、`--gc-color-surface-*` | 卡片、面板、弹窗、表单控件等容器背景 |
| 文字 | `--gc-color-text`、`--gc-color-text-muted`、`--gc-color-text-strong`、`--gc-color-text-soft`、`--gc-color-text-inverse`、`--gc-color-text-inverse-muted` | 各级文字颜色 |
| 边框 | `--gc-color-border`、`--gc-color-border-subtle`、`--gc-color-border-soft`、`--gc-color-border-strong`、`--gc-color-border-muted` | 分隔线、输入框边框 |
| 主色 | `--gc-color-primary`、`--gc-color-primary-hover`、`--gc-color-primary-strong`、`--gc-color-primary-border`、`--gc-color-primary-border-strong`、`--gc-color-primary-weak`、`--gc-color-primary-soft` | 品牌主色调及变体 |
| 语义色 | `--gc-color-success`、`--gc-color-warning`、`--gc-color-danger`、`--gc-color-info` | 成功/警告/危险/信息 |
| 语义色配套 | `--gc-color-{semantic}-bg`、`--gc-color-{semantic}-soft`、`--gc-color-{semantic}-border` | 对应的背景、软背景、边框 |
| 辅助 | `--gc-color-accent-purple`、`--gc-color-code-bg`、`--gc-color-muted`、`--gc-color-muted-bg`、`--gc-color-focus`、`--gc-color-focus-ring`、`--gc-color-backdrop` | 代码块底色、禁用态、聚焦环、遮罩等 |

**语义色四件套模式：** 每个语义色（success / warning / danger / info）必须有 4 个配套变量：

```
--gc-color-{semantic}          → 前景色（文字/图标）
--gc-color-{semantic}-bg       → 背景色
--gc-color-{semantic}-soft     → 更柔和的背景色
--gc-color-{semantic}-border   → 边框色
```

#### 阴影 (`--gc-shadow-*`)

| 变量 | 用途 |
|---|---|
| `--gc-shadow-sm` | 小元素（标签、徽章） |
| `--gc-shadow-md` | 卡片默认悬浮 |
| `--gc-shadow-lg` | 弹窗、下拉菜单 |
| `--gc-shadow-hover` | 鼠标悬浮反馈 |
| `--gc-shadow-overlay` | 模态框遮罩 |
| `--gc-shadow-primary` | 主色按钮聚焦/悬浮 |
| `--gc-shadow-focus` | 通用聚焦环 |

#### 间距 (`--gc-space-*`)

`--gc-space-hairline` 用于 `1px` 发丝线边框；通用尺度继续使用 `--gc-space-1` ~ `--gc-space-12`。紧凑排版和控件密度使用 `--gc-space-tight`（2px）、`--gc-space-compact`（6px）、`--gc-space-control`（10px）、`--gc-space-panel`（14px）、`--gc-space-section`（20px）和 `--gc-space-viewport`（24px）；模态框需要紧凑详情布局时使用 `--gc-space-modal-detail-y`（15px）。徽章和芯片使用对应的 `badge` / `chip` 间距令牌。不允许在组件中硬编码 `px` 间距值。

#### 边框 (`--gc-border-*`)

`--gc-border-width-default` 表示默认边框宽度。组件必须通过该语义变量设置边框宽度，不得使用裸 `px` 或 `thin`、`medium`、`thick` 等关键字。

## 四、主题切换机制

### 4.1 驱动方式

```css
/* 亮色（默认） */
:root,
:root[data-theme="light"] { ... }

/* 暗色 */
:root[data-theme="dark"] { ... }
```

切换主题的本质是修改 `<html data-theme="...">` 属性，CSS 层叠自动替换所有 `var(--gc-*)` 的实际值。

### 4.2 代码调用链

```
GcThemeToggle.vue（用户点击）
  → appStore.setTheme('light'|'dark')
    → applyThemeToDocument(theme)   // 设置 document.documentElement.dataset.theme
    → updatePreferences()            // 同步偏好到后端
    → writeCachedPreferences()       // 写入 localStorage
```

TypeScript 入口：`web/src/preferences/app-preferences.ts` → `applyThemeToDocument()`

### 4.3 组件开发中的主题适配规则

**强制要求：**

- 组件 `<style scoped>` 中**禁止**出现硬编码的颜色值（如 `#ffffff`、`rgb(0,0,0)`、`#333` 等）。
- **必须**使用 `var(--gc-color-*)` 引用语义化变量。
- 如需新增颜色变量，**必须**在 `tokens/index.css` 中同步定义亮色和暗色两套值。
- 不允许在组件内通过 `@media (prefers-color-scheme: dark)` 覆盖颜色——暗色切换完全由 `data-theme` 属性驱动。

**正确示例：**

```css
/* ✅ 正确 */
.my-card {
  background: var(--gc-color-surface);
  border: 1px solid var(--gc-color-border);
  color: var(--gc-color-text);
  border-radius: var(--gc-radius-md);
  box-shadow: var(--gc-shadow-md);
}

.my-card__title {
  color: var(--gc-color-text-strong);
  font-size: var(--gc-font-size-lg);
}

.my-card__muted {
  color: var(--gc-color-text-muted);
  font-size: var(--gc-font-size-sm);
}
```

**错误示例：**

```css
/* ❌ 错误——硬编码颜色 */
.my-card {
  background: #ffffff;
  border: 1px solid #e5e7eb;
  color: #111827;
}

/* ❌ 错误——硬编码间距 */
.my-card {
  padding: 16px;        /* 应使用 var(--gc-space-4) */
  margin-bottom: 8px;    /* 应使用 var(--gc-space-2) */
}

/* ❌ 错误——通过媒体查询覆盖暗色 */
@media (prefers-color-scheme: dark) {
  .my-card { background: #1f2937; }
}
```

### 4.4 如果确实需要新颜色

按以下步骤操作：

1. 在 `tokens/index.css` 的亮色块 (`:root[data-theme="light"]`) 中新增变量
2. 在暗色块 (`:root[data-theme="dark"]`) 中定义对应的暗色值
3. 命名遵循 `--gc-color-{语义角色}` 规范
4. 在组件中使用 `var(--gc-color-xxx)` 引用

## 五、Status/Risk 色调系统

`web/src/design-system/status/status-map.ts` 和 `risk-map.ts` 定义了统一的色调类型：

```typescript
type StatusTone = 'success' | 'warning' | 'danger' | 'info' | 'muted'
```

设计系统组件（`GcStatusTag`、`GcRiskBadge`）通过 CSS class 修饰符映射到语义色变量：

```css
.gc-tag--success { color: var(--gc-color-success); background: var(--gc-color-success-bg); }
.gc-tag--warning { color: var(--gc-color-warning); background: var(--gc-color-warning-bg); }
.gc-tag--danger  { color: var(--gc-color-danger);  background: var(--gc-color-danger-bg); }
.gc-tag--info    { color: var(--gc-color-info);    background: var(--gc-color-info-bg); }
.gc-tag--muted   { color: var(--gc-color-muted);   background: var(--gc-color-muted-bg); }
```

**新增组件如果需要状态色调**，必须复用 `StatusTone` 类型和相同的 CSS class → 语义色变量映射模式，不得自行定义新的颜色映射。

### 6.1 Cloud Security Pro 基础组件接口

以下组件是 `001.3.1` 页面迁移的统一视觉入口。组件只接收显示投影和已翻译文本，不拥有业务 API、权限判断或主题状态。

| 组件 | 必须遵守的接口边界 |
|---|---|
| `GcButton` | `variant` 只允许 `primary`、`secondary`、`ghost`、`icon`；`loading` 自动禁用；图标按钮必须传入翻译后的 `ariaLabel` 和 `title` |
| `GcCard` | 通过 `header`、默认内容/`body`、`footer` 插槽表达层级；`interactive` 和 `selected` 只表达视觉状态 |
| `GcProgressBar` | `value`、`max`、`tone` 和翻译后的 `ariaLabel` 必须完整传入；进度不能只依赖颜色 |
| `GcSelectionCard` | 通过 `v-model` 或 `select` 事件回传选择；使用 `aria-pressed` 表达选中态；禁用态不触发业务事件 |
| `GcModal` | 统一遮罩、焦点捕获、Escape、焦点恢复、提交中禁用和错误承载，业务页面不得复制模态框实现 |
| `GcSimpleFlowWizard` / `GcUserFlowWizard` | 只承载步骤导航和 slot 内容；步骤标题、帮助和 ARIA 名称必须由 i18n 提供 |

这些组件的颜色、间距、圆角、阴影、字号和字体必须通过 `--gc-*` 令牌消费。新增组件若要表达状态，必须复用 `StatusTone` 及同一套 CSS class 到语义色映射，禁止创建独立的颜色枚举。

## 八、Cloud Security Pro 组件视觉语言

本节将 CertVault 与 CertFlow 示例归纳为 GCAC 的“专业云端安全风格（Cloud Security Pro）”。它强调安全感、高效率和极简层级，服务于持续查看证书、资产、监控和执行状态的运维用户。

### 8.1 色彩语义

示例中的色值只是视觉取证基准，不能直接写入 Vue、TypeScript 或组件 `<style>`。正式实现必须映射到 `tokens/index.css` 的语义变量，并为 light/dark 提供可读值。

| 示例视觉角色 | 取证参考 | 正式实现入口 | 使用边界 |

暗色主题不得简单反转亮色值。导航、表面、字段、遮罩、语义状态和图表都必须使用对应的暗色变量，并通过对比度检查。

#### 8.1.1 Cloud Security Pro 令牌映射

CertFlow 的控制台、证书卡和 CertVault 的来源选择流程只能消费下表已有令牌。表中的多个令牌表达同一层级在不同状态下的变化，不表示可以在页面内随意挑选或新增同义变量。

| 视觉角色 | 必须使用的既有令牌 | 使用规则 |

| 页面画布与工作台底色 | `--gc-color-bg`、`--gc-color-bg-strong` | 仅用于应用背景、固定 Shell 的衬底和分区，不将其伪装成内容卡片 |

| 键盘焦点与禁用态 | `--gc-color-focus`、`--gc-color-focus-ring`、`--gc-shadow-focus`、`--gc-color-disabled`、`--gc-color-disabled-bg`、`--gc-opacity-disabled` | 焦点必须可见，禁用态既不接收交互也不只靠降低透明度表达 |

所有尺寸继续使用现有的 `--gc-space-*`、`--gc-control-height-*`、`--gc-size-*`、`--gc-radius-*`、`--gc-shadow-*` 和 `--gc-font-*`。本规范不为示例中的 Tailwind 色名、间距值或圆角名称创建别名。

#### 8.1.2 亮色/暗色主题合同

- `:root` 与 `:root[data-theme="light"]` 是亮色基线，`:root[data-theme="dark"]` 为同一语义令牌提供暗色值；组件只能引用变量，不能根据当前主题分支选择另一套 class 或色值。
- 新页面至少验证页面画布、导航当前项、卡片、字段默认/聚焦态、选择卡、状态标签、进度条、Modal 遮罩和禁用按钮在两套主题下的可读性。暗色主题要保持层级区分，不能把所有容器压成同一种深色。
- 原生表单控件的配色由 `color-scheme` 和字段令牌共同承担。组件中不得用 `@media (prefers-color-scheme: dark)` 覆盖颜色；系统偏好只可参与应用初始主题决策，不能绕开 `<html data-theme>`。
- 新增颜色令牌前必须先证明现有语义无法表达，再同时补齐 light/dark 两个块并更新本规范；不得新建按色值命名、页面私有或 `legacy` 桥接变量。

#### 8.2.1 工作台导航

- CertFlow 的一级导航采用稳定的左侧工作台 Shell：桌面端使用 `--gc-size-shell-sidebar`，图标和文字间距使用 `--gc-space-nav-gap`；小屏幕收束为可关闭抽屉，不能同时渲染两套可操作导航。
- 当前一级菜单使用主色表面与反白文字，非当前项使用普通文字与弱表面悬停反馈；当前状态还必须通过路由状态和 `aria-current="page"` 表达，不能只靠蓝色背景区分。
- 顶部的证书分类、视图切换等二级导航统一使用 `GcTabs` 或既有分段控制样式。每个标签保留可见名称、键盘焦点和激活状态，不把普通操作伪装成导航，也不把导航伪装成按钮。
- 导航项使用熟悉图标辅助扫描，但图标不能替代可访问名称。折叠导航时，图标按钮必须带 i18n `aria-label`、tooltip 和可恢复的文字导航。
- 导航 Shell、头部和主内容是页面结构，不得套进悬浮大卡片；`surface-glass` 可作为默认卡片、列表和表格外层的轻玻璃表面，避免把整页做成装饰性玻璃卡片。
- `backdrop-filter` 只可用于侧栏、顶部栏、共享 Modal/下拉浮层和少数关键概览面板；普通卡片、列表、表格和高频 hover 禁止使用或动画化该滤镜。
- 表格只允许最外层容器按需使用一层滤镜；表头、行、单元格及分页栏不得各自使用滤镜。高频行 hover 只能变更背景、边框或轻阴影。

### 8.3 按钮、标签和进度条

- Primary 按钮使用主色实心表面、清晰的 hover/pressed/disabled/loading 状态和可见焦点环；危险操作必须改用 `danger` 语义，不得只靠颜色区分。
- Secondary 按钮使用表面色、语义边框和轻微悬停阴影；Ghost/Icon 按钮默认不显示容器，悬停时显示弱表面。
- 当存在明确的熟悉图标时优先使用图标按钮；图标按钮必须提供 i18n ARIA 标签和 tooltip，不用文字胶囊替代图标。
- 权限门控按钮继续使用 `GcPermissionButton` 或其共享样式，业务页面不能重新实现权限判断。
- 状态标签统一使用 `StatusTone`，采用浅色背景/语义前景色/可选边框；示例中的 12px 加粗只是目标，正式字号使用字体令牌。
- 表单分类标签可以使用约 10px、全大写和宽字距；它只用于分类层级，不得把所有业务文案强制转换为大写。
- 进度条使用约 6-8px 的稳定高度、圆润端点和语义填充色；数值、状态和可访问名称必须由调用者传入，不能只用颜色表达进度。

按钮、标签和进度的完整交互合同如下：

- 新建可复用按钮优先通过 `GcButton` 的 `primary`、`secondary`、`ghost`、`icon` 变体表达；存量原生按钮必须复用同一套全局 `.gc-button` / `.gc-icon-button` 语义样式，禁止在业务 View 复制另一套按钮规则。`primary` 每个局部操作区通常只保留一个；加载时设置 `loading` 并禁用重复提交。`GcButton` 当前没有 `danger` 变体，危险确认必须由 `GcConfirmAction` 或等价的共享确认流程承载 `danger` 语义，不能临时给页面按钮硬编码红色样式。
- Icon 按钮仅用于新增、编辑、关闭、返回、通知等可由熟悉图标准确表达的动作。无可见文字时必须提供 i18n `aria-label` 和 tooltip；不使用仅靠颜色或悬停后才出现的文字说明关键动作。
- `GcStatusTag`、`GcRiskBadge` 和 `GcProgressBar` 必须复用 `StatusTone`。标签需展示已翻译的状态文字；进度组件需暴露 `value`、`max`、`tone` 和已翻译 `ariaLabel`，渲染为原生 `progress` 或等价的 `role="progressbar"`、`aria-valuemin`、`aria-valuemax`、`aria-valuenow` 语义。
- 证书到期条、监控条和资源条的颜色应映射到 `success`、`warning`、`danger` 或 `info`，同时显示可读的剩余时间、百分比或状态。所有展示给用户的日期和时间仍必须转换为浏览器本地时间。

### 8.4 卡片和模态框

- 卡片结构优先采用 Header / Body / Footer：Header 为图标加标题，右侧放状态；Body 展示核心指标、到期进度或风险信息；Footer 放主要动作和次要动作。
- 卡片的主要动作应保持明确的主次关系，主操作占据主要视觉权重，编辑、详情等辅助动作不得抢夺主操作焦点。
- 交互式选择卡默认使用较强边框和表面色；选中态使用主色边框和弱主色背景；悬停态只提升边框/表面，不改变业务状态。
- `GcModal` 必须支持遮罩、焦点捕获、Escape 关闭、关闭后焦点恢复、提交中禁用和错误反馈。遮罩可使用弱化背景配合共享模糊效果，但不允许在页面中复制一套 Modal。
- 模态框流程可以提供左上角圆形返回按钮；返回、关闭、取消和提交的含义必须通过 i18n 和可访问名称区分。
- 输入框使用字段表面、语义边框和焦点环；不能依赖示例的 Tailwind `ring-*` class，也不能移除键盘焦点。

#### 8.4.1 表单与交互选择卡

- 每个输入、选择框和文本域必须有可见 i18n 标签；placeholder 只提供示例或格式提示，不能充当标签。帮助、校验错误和格式限制通过 `aria-describedby` 关联，错误状态使用 `aria-invalid` 和语义色四件套共同表达。
- 普通字段和搜索字段使用 `--gc-color-surface-field`、语义边框、`--gc-radius-control` 及既有 `--gc-control-height-*`；聚焦时切换到字段焦点表面和共享焦点环。密钥和私密凭据继续使用 `GcSecretInput`，不得在业务页复制可见性切换逻辑。
- CertVault 的“导入已有证书 / 通过 ACME 申请”等来源入口使用 `GcSelectionCard`。默认态为表面与强边框，悬停只提供可操作反馈，选中态使用 `surface-selected`、主色边框和非颜色提示；禁用态不触发 `select` 事件。
- `GcSelectionCard` 当前是原生 `button`，以 `aria-pressed` 输出受控选择状态，因此天然支持 Tab、Enter 和 Space。单选来源的分组语义、互斥状态和已翻译分组名称由调用方容器承担；需要多选时必须使用对应的复选控件或明确的复选组语义，不得把普通 `div` 加 click 事件伪装成可选择控件。
- 卡片内的表单分区优先按步骤、字段组和提交动作排列。禁止为了视觉效果再包一层无业务边界的卡片，避免卡片嵌卡片导致层级混乱。

#### 8.4.2 模态框与流程容器

- `GcModal` 是唯一的通用浮层入口，使用 `--gc-size-modal-default`、`--gc-radius-modal`、`--gc-space-modal-x`、`--gc-space-modal-y` 和遮罩/阴影令牌。尺寸档位必须映射到 `--gc-size-modal-confirm`、`--gc-size-modal-default`、`--gc-size-modal-lg`、`--gc-size-modal-xl`、`--gc-size-modal-xxl` 等既有令牌；不得在业务页面写裸宽度。
- Modal 打开后必须具备 `role="dialog"`、`aria-modal="true"`、指向标题的 `aria-labelledby`，并把初始焦点置于有意义的元素。键盘焦点不得逃逸到背景；关闭后恢复到启动 Modal 的元素。
- 关闭按钮、取消、返回和确认操作都必须可键盘访问且语义不同。Escape 只能关闭可取消的浮层；执行中、存在未保存数据或破坏性确认时，关闭行为必须先遵循明确的业务保护流程。
- CertVault 的多步骤流程优先复用 `GcSimpleFlowWizard` 或 `GcUserFlowWizard`。当证书导入确实需要格式、材料和校验结果的业务状态时，`CertificateImportForm` 可以拥有步骤编排，但必须复用同一套按钮、Modal、令牌和步骤可访问性合同，不能另建主题或浮层实现；返回按钮和步骤状态必须保留可访问名称，错误消息必须在当前步骤内可感知，不能依靠短暂动效传递结果。

#### 8.4.3 趋势图与环形状态图

- `GcTrendChart` 和 `GcDonutChart` 是 Cloud Security Pro 的轻量图表表面，不引入外部 CDN、ApexCharts 或页面内图表运行时；两者只接收调用方已经获得的展示数据，绝不直接请求业务 API。
- `GcTrendChart` 的输入固定为按调用方顺序排列的 `readonly { value: number }[]`、翻译后的 `ariaLabel`、翻译后的 `emptyLabel`、可选 `StatusTone`、可选数值单位和可选 `showYAxis`。非有限数值必须被安全忽略；缺口不得被伪造为连续趋势；空数据必须显示调用方传入的可见空态；单位由业务调用方按数据语义传入，未提供时不显示。`showYAxis` 默认关闭，保留紧凑趋势图的完整绘图区和 3 条水平网格线；仅在调用方开启时显示 4 个与网格线对齐的纵轴刻度，绘图区为实际数据范围保留少量上下边距；所有有效值相同时只显示一个中心刻度，避免重复标签。
- `GcDonutChart` 的输入固定为 `readonly { value: number; tone: StatusTone }[]`、翻译后的 `ariaLabel` 和翻译后的 `emptyLabel`，可选 `center` 插槽只承载调用方提供的中心摘要。非正数或非有限数值必须被安全忽略，未知 tone 归入 `muted`；分段颜色只能来自 StatusTone 映射。
- 两个图表均以非交互 `role="img"` 加已翻译名称承载基础可访问性。图例、数值、单位、筛选、tooltip 和重试入口属于业务页面，不能藏进图表组件；空态、窄容器、亮暗主题和减少动态效果必须有组件合同测试。

### 8.5 排版、动效和实现边界

- 页面标题使用紧凑的强调层级；描述和元数据使用弱化文字；卡片中的核心数据优先展示并使用合适的状态语义。
- 示例的 `animate-in`、淡入和缩放只表示交互意图，正式实现使用共享 CSS 动效并尊重 `prefers-reduced-motion`，不能引入 Tailwind 运行时。
- 图标使用项目已有的本地图标入口或已批准的图标库；禁止 Font Awesome、Google Fonts、外部头像和 CDN 运行时依赖。
- 组件样式必须从语义令牌、设计系统组件和共享布局模式获得；页面不得复制颜色、圆角、阴影、按钮、标签或 Modal 规则。
- 这些规则只描述视觉与交互承载方式，不改变业务 API、权限、状态机、时间存储或国际化资源所有权。

### 8.6 可访问性与质量门槛

- 所有交互控件必须可通过键盘完成操作，并在任意主题下拥有不依赖颜色的可见焦点。不能通过 `outline: none` 清除焦点后不提供共享焦点环。
- 文本、图标和状态底色需要满足可读对比度；成功、警告、危险和信息状态必须同时提供文字、图标、数值或结构性提示，不能只用色相传达结果。
- 图标、关闭按钮、导航缩略项、进度条、选择卡、表单帮助和 Modal 的 ARIA 文案全部走 `vue-i18n`。业务组件不得硬编码自然语言、ARIA fallback 或 tooltip 文本。
- 进入、退出、悬停和选择动效仅用于反馈，不可阻塞完成任务。动效使用共享 CSS，并通过 `prefers-reduced-motion` 降级为无位移或无动画的状态变化。
- 证书签发、过期、部署和监控事件中的可见时间统一使用浏览器本地时间格式化工具；不得把 UTC/ISO 原文作为视觉语言的一部分。

### 8.7 禁止项

- 禁止把示例中的 Tailwind、Font Awesome、Google Fonts、第三方头像、图表脚本或 CDN 依赖直接带入正式前端；图标和资源必须使用项目已有的本地入口或已批准依赖。
- 禁止复制示例中的硬编码色值、`px` 尺寸、`rounded-*`、`shadow-*`、`ring-*` 等原子类含义到业务组件。所有视觉值必须通过现有语义令牌和共享组件表达。
- 禁止新增第二套页面风格、业务页私有按钮/卡片/Modal/选择卡实现，或在旧样式旁并列新的工作台样式。迁移页面必须收敛到同一套 Cloud Security Pro 令牌和设计系统组件。
- 禁止添加装饰性渐变球、模糊光斑、无业务信息的玻璃浮层或营销式大 Hero；安全运维控制台优先信息密度、可扫描性和可重复操作。
- 禁止用样式覆盖权限、状态机、时间格式化、国际化或业务校验，也不得以视觉重构为理由改变既有 API、权限边界和用户可见行为。

## 九、检查清单

新建或修改前端组件时，确认以下事项：

- [ ] 无硬编码颜色值（`#xxx`、`rgb()`、`hsl()` 等）
- [ ] 颜色引用全部使用 `var(--gc-color-*)` 格式
- [ ] 间距使用 `var(--gc-space-*)`，不写裸 `px`
- [ ] 边框宽度使用 `var(--gc-border-width-default)`
- [ ] 圆角使用 `var(--gc-radius-*)`
- [ ] 阴影使用 `var(--gc-shadow-*)`
- [ ] 字号使用 `var(--gc-font-size-*)`
- [ ] 字体族使用 `var(--gc-font-family)`
- [ ] 不通过 `@media (prefers-color-scheme: dark)` 覆盖颜色
- [ ] 不新增 `--gc-color-legacy-*` 变量
- [ ] 可复用 UI 组件放入 `design-system/components/`
- [ ] 全局布局样式放入 `design-system/patterns/layout.css`
- [ ] Primary/Secondary/Ghost/Icon 按钮均有 hover、focus、disabled、loading 或危险态合同
- [ ] 卡片、交互选择卡、状态标签和进度条遵守 Header/Body/Footer 与 StatusTone 规则
- [ ] 导航当前项有路由状态和 `aria-current`，移动端不会与桌面导航并列为两套可操作入口
- [ ] 输入控件具有可见标签、帮助/错误关联、焦点环和语义化错误状态
- [ ] 选择卡支持键盘选择、已翻译名称和非颜色化的选中反馈
- [ ] 趋势图与环形图只消费结构化展示数据、StatusTone 和已翻译的 ARIA/空态文案，不引入外部图表运行时
- [ ] Modal 具备遮罩、焦点捕获、Escape、焦点恢复、提交中和错误状态
- [ ] light/dark 下已检查画布、导航、字段、选择卡、状态、进度、遮罩与禁用态的可读性
- [ ] ARIA、tooltip、状态文字和用户可见时间符合 i18n 与浏览器本地时间规范
- [ ] 新增动效尊重 `prefers-reduced-motion`，且不引入 Tailwind 或外部 CDN
- [ ] 未复制示例的装饰性光斑、外部资源或第二套页面样式
