# GCAC 前端主题变量规范

> 版本：1.3 | 更新日期：2026-08-12 | 适用范围：`web/src/` 所有前端代码

---

## 一、概述

GCAC 前端采用**语义化 CSS 自定义属性（CSS Custom Properties）**作为唯一的设计令牌系统，实现亮色/暗色双主题无缝切换。工作台页面的具体视觉语言由 `001.3.1-控制台工作台视觉重构与主题适配` 维护，本文件负责令牌、主题切换和组件消费规则。

- **不使用** Tailwind CSS、UnoCSS 或任何原子化 CSS 框架。
- **不使用** CSS-in-JS 方案。
- **所有设计令牌**统一定义在 `web/src/design-system/tokens/index.css`，全项目仅此一处来源。

主题切换通过 `<html>` 元素的 `data-theme` 属性驱动：移除或设置 `data-theme="light"` 为亮色、`data-theme="dark"` 为暗色。

## 二、CSS 变量命名规范

### 2.1 命名格式

```
--gc-{类别}-{属性}[-{修饰符}]
```

| 部分 | 说明 |
|---|---|
| `gc` | 项目固定前缀 |
| `{类别}` | 取值：`color`、`space`、`font`、`radius`、`shadow`、`gradient` |
| `{属性}` | 语义化属性名，如 `bg`、`text`、`border`、`primary`、`surface` |
| `{修饰符}` | 可选，进一步细分，如 `strong`、`muted`、`soft`、`hover`、`sm` |

### 2.2 已定义令牌类别

#### 颜色 (`--gc-color-*`)

按**语义角色**命名，而非按色值命名：

| 语义组 | 变量示例 | 说明 |
|---|---|---|
| 背景 | `--gc-color-bg`、`--gc-color-bg-strong` | 页面底色 |
| 表面 | `--gc-color-surface`、`--gc-color-surface-*` | 卡片、面板、弹窗、表单控件等容器背景 |
| 文字 | `--gc-color-text`、`--gc-color-text-muted`、`--gc-color-text-strong`、`--gc-color-text-soft`、`--gc-color-text-inverse`、`--gc-color-text-inverse-muted` | 各级文字颜色 |
| 边框 | `--gc-color-border`、`--gc-color-border-subtle`、`--gc-color-border-soft`、`--gc-color-border-strong`、`--gc-color-border-muted` | 分隔线、输入框边框 |
| 主色 | `--gc-color-primary`、`--gc-color-primary-hover`、`--gc-color-primary-strong`、`--gc-color-primary-border`、`--gc-color-primary-border-strong`、`--gc-color-primary-weak`、`--gc-color-primary-soft` | 品牌主色调及变体 |
| 语义色 | `--gc-color-success`、`--gc-color-warning`、`--gc-color-danger`、`--gc-color-info` | 成功/警告/危险/信息 |
| 语义色配套 | `--gc-color-{semantic}-bg`、`--gc-color-{semantic}-soft`、`--gc-color-{semantic}-border` | 对应的背景、软背景、边框 |
| 辅助 | `--gc-color-accent-purple`、`--gc-color-code-bg`、`--gc-color-muted`、`--gc-color-muted-bg`、`--gc-color-focus`、`--gc-color-focus-ring`、`--gc-color-backdrop` | 代码块底色、禁用态、聚焦环、遮罩等 |

**语义色四件套模式：** 每个语义色（success / warning / danger / info）必须有 4 个配套变量：

```
--gc-color-{semantic}          → 前景色（文字/图标）
--gc-color-{semantic}-bg       → 背景色
--gc-color-{semantic}-soft     → 更柔和的背景色
--gc-color-{semantic}-border   → 边框色
```

#### 阴影 (`--gc-shadow-*`)

| 变量 | 用途 |
|---|---|
| `--gc-shadow-sm` | 小元素（标签、徽章） |
| `--gc-shadow-md` | 卡片默认悬浮 |
| `--gc-shadow-lg` | 弹窗、下拉菜单 |
| `--gc-shadow-hover` | 鼠标悬浮反馈 |
| `--gc-shadow-overlay` | 模态框遮罩 |
| `--gc-shadow-primary` | 主色按钮聚焦/悬浮 |
| `--gc-shadow-focus` | 通用聚焦环 |

#### 间距 (`--gc-space-*`)

`--gc-space-hairline` 用于 `1px` 发丝线边框；通用尺度继续使用 `--gc-space-1` ~ `--gc-space-12`。紧凑排版和控件密度使用 `--gc-space-tight`（2px）、`--gc-space-compact`（6px）、`--gc-space-control`（10px）、`--gc-space-panel`（14px）、`--gc-space-section`（20px）和 `--gc-space-viewport`（24px）；徽章和芯片使用对应的 `badge` / `chip` 间距令牌。不允许在组件中硬编码 `px` 间距值。

#### 边框 (`--gc-border-*`)

`--gc-border-width-default` 表示默认边框宽度。组件必须通过该语义变量设置边框宽度，不得使用裸 `px` 或 `thin`、`medium`、`thick` 等关键字。

#### 排版 (`--gc-font-*`)

| 类别 | 变量 |
|---|---|
| 字体族 | `--gc-font-family`（SF Pro → PingFang SC → Microsoft YaHei 降级链） |
| 字号 | 通用尺度：`--gc-font-size-xs`(12px) / `sm`(14px) / `md`(16px) / `lg`(20px) / `xl`(28px) / `2xl`(40px)；语义尺度：`overline`(10px)、`caption`(11px)、`label`(13px)、`body`(15px)、`body-lg`(17px)、`heading-xs`(18px)、`heading-sm`(22px)、`heading-md`(24px) |
| 行高 | `--gc-line-height-tight` / `--gc-line-height-relaxed` |

#### 圆角 (`--gc-radius-*`)

| 变量 | 值 | 典型用途 |
|---|---|---|
| `--gc-radius-sm` | 10px | 小按钮、标签、输入框 |
| `--gc-radius-md` | 14px | 卡片、面板 |

| `--gc-radius-xl` | 24px | 最大圆角（模态框等） |
| `--gc-radius-full` | 999px | 圆形徽标、分段流程节点 |

#### 通用尺寸与状态 (`--gc-*`)

| 变量 | 典型用途 |
|---|---|
| `--gc-border-width` | 标准边框宽度 |
| `--gc-control-height-md` | 标准中等控件高度 |
| `--gc-control-height-sm` | 紧凑按钮、状态控件高度 |

| `--gc-size-modal-wide` | 新建、编辑向导类宽模态框的最大宽度 |
| `--gc-size-provider-logo` | 云 Provider 标识在选择卡片中的横向展示尺寸 |
| `--gc-size-provider-logo-height` | 云 Provider 标识在选择卡片中的纵向展示尺寸 |
| `--gc-opacity-disabled` | 禁用态透明度 |
| `--gc-size-shell-sidebar` | 桌面工作台左侧导航稳定宽度 |
| `--gc-size-modal-default` | Cloud Security Pro Modal 默认最大宽度 |
| `--gc-size-progress` | 状态进度条稳定高度 |
| `--gc-size-progress-compact` | 紧凑进度条高度 |
| `--gc-size-icon-sm` / `md` / `lg` | 14px / 20px / 24px 图标稳定尺寸 |
| `--gc-size-modal-confirm` / `--gc-size-modal-xxl` | 确认模态框和大结果模态框宽度 |
| `--gc-size-menu-*` | 用户菜单、语言菜单及其视口约束 |

## 四、主题切换机制

### 4.1 驱动方式

```css
/* 亮色（默认） */
:root,
:root[data-theme="light"] { ... }

/* 暗色 */
:root[data-theme="dark"] { ... }
```

切换主题的本质是修改 `<html data-theme="...">` 属性，CSS 层叠自动替换所有 `var(--gc-*)` 的实际值。

### 4.2 代码调用链

```
GcThemeToggle.vue（用户点击）
  → appStore.setTheme('light'|'dark')
    → applyThemeToDocument(theme)   // 设置 document.documentElement.dataset.theme
    → updatePreferences()            // 同步偏好到后端
    → writeCachedPreferences()       // 写入 localStorage
```

TypeScript 入口：`web/src/preferences/app-preferences.ts` → `applyThemeToDocument()`

### 4.3 组件开发中的主题适配规则

**强制要求：**

- 组件 `<style scoped>` 中**禁止**出现硬编码的颜色值（如 `#ffffff`、`rgb(0,0,0)`、`#333` 等）。
- **必须**使用 `var(--gc-color-*)` 引用语义化变量。
- 如需新增颜色变量，**必须**在 `tokens/index.css` 中同步定义亮色和暗色两套值。
- 不允许在组件内通过 `@media (prefers-color-scheme: dark)` 覆盖颜色——暗色切换完全由 `data-theme` 属性驱动。

**正确示例：**

```css
/* ✅ 正确 */
.my-card {
  background: var(--gc-color-surface);
  border: 1px solid var(--gc-color-border);
  color: var(--gc-color-text);
  border-radius: var(--gc-radius-md);
  box-shadow: var(--gc-shadow-md);
}

.my-card__title {
  color: var(--gc-color-text-strong);
  font-size: var(--gc-font-size-lg);
}

.my-card__muted {
  color: var(--gc-color-text-muted);
  font-size: var(--gc-font-size-sm);
}
```

**错误示例：**

```css
/* ❌ 错误——硬编码颜色 */
.my-card {
  background: #ffffff;
  border: 1px solid #e5e7eb;
  color: #111827;
}

/* ❌ 错误——硬编码间距 */
.my-card {
  padding: 16px;        /* 应使用 var(--gc-space-4) */
  margin-bottom: 8px;    /* 应使用 var(--gc-space-2) */
}

/* ❌ 错误——通过媒体查询覆盖暗色 */
@media (prefers-color-scheme: dark) {
  .my-card { background: #1f2937; }
}
```

### 4.4 如果确实需要新颜色

按以下步骤操作：

1. 在 `tokens/index.css` 的亮色块 (`:root[data-theme="light"]`) 中新增变量
2. 在暗色块 (`:root[data-theme="dark"]`) 中定义对应的暗色值
3. 命名遵循 `--gc-color-{语义角色}` 规范
4. 在组件中使用 `var(--gc-color-xxx)` 引用

## 五、Status/Risk 色调系统

`web/src/design-system/status/status-map.ts` 和 `risk-map.ts` 定义了统一的色调类型：

```typescript
type StatusTone = 'success' | 'warning' | 'danger' | 'info' | 'muted'
```

设计系统组件（`GcStatusTag`、`GcRiskBadge`）通过 CSS class 修饰符映射到语义色变量：

```css
.gc-tag--success { color: var(--gc-color-success); background: var(--gc-color-success-bg); }
.gc-tag--warning { color: var(--gc-color-warning); background: var(--gc-color-warning-bg); }
.gc-tag--danger  { color: var(--gc-color-danger);  background: var(--gc-color-danger-bg); }
.gc-tag--info    { color: var(--gc-color-info);    background: var(--gc-color-info-bg); }
.gc-tag--muted   { color: var(--gc-color-muted);   background: var(--gc-color-muted-bg); }
```

**新增组件如果需要状态色调**，必须复用 `StatusTone` 类型和相同的 CSS class → 语义色变量映射模式，不得自行定义新的颜色映射。

### 6.1 Cloud Security Pro 基础组件接口

以下组件是 `001.3.1` 页面迁移的统一视觉入口。组件只接收显示投影和已翻译文本，不拥有业务 API、权限判断或主题状态。

| 组件 | 必须遵守的接口边界 |
|---|---|
| `GcButton` | `variant` 只允许 `primary`、`secondary`、`ghost`、`icon`；`loading` 自动禁用；图标按钮必须传入翻译后的 `ariaLabel` 和 `title` |
| `GcCard` | 通过 `header`、默认内容/`body`、`footer` 插槽表达层级；`interactive` 和 `selected` 只表达视觉状态 |
| `GcProgressBar` | `value`、`max`、`tone` 和翻译后的 `ariaLabel` 必须完整传入；进度不能只依赖颜色 |
| `GcSelectionCard` | 通过 `v-model` 或 `select` 事件回传选择；使用 `aria-pressed` 表达选中态；禁用态不触发业务事件 |
| `GcModal` | 统一遮罩、焦点捕获、Escape、焦点恢复、提交中禁用和错误承载，业务页面不得复制模态框实现 |
| `GcSimpleFlowWizard` / `GcUserFlowWizard` | 只承载步骤导航和 slot 内容；步骤标题、帮助和 ARIA 名称必须由 i18n 提供 |

这些组件的颜色、间距、圆角、阴影、字号和字体必须通过 `--gc-*` 令牌消费。新增组件若要表达状态，必须复用 `StatusTone` 及同一套 CSS class 到语义色映射，禁止创建独立的颜色枚举。

## 八、Cloud Security Pro 组件视觉语言

本节将 CertVault 与 CertFlow 示例归纳为 GCAC 的“专业云端安全风格（Cloud Security Pro）”。它强调安全感、高效率和极简层级，服务于持续查看证书、资产、监控和执行状态的运维用户。

### 8.1 色彩语义

示例中的色值只是视觉取证基准，不能直接写入 Vue、TypeScript 或组件 `<style>`。正式实现必须映射到 `tokens/index.css` 的语义变量，并为 light/dark 提供可读值。

| 示例视觉角色 | 取证参考 | 正式实现入口 | 使用边界 |
|---|---|---|---|
| 品牌主色 | Blue-600（`#2563EB`） | `--gc-color-primary`、`--gc-color-primary-hover`、`--gc-color-primary-strong` | 主按钮、当前导航、重要进度和选中态 |
| 页面背景 | Slate-50（`#F8FAFC`） | `--gc-color-bg`、`--gc-color-bg-strong` | 仅作为页面画布，不作为卡片内容底色 |
| 内容表面 | White（`#FFFFFF`） | `--gc-color-surface-solid`、`--gc-color-surface-overlay` | 卡片、表单、弹窗和详情面板 |
| 标题文字 | Slate-800（`#1E293B`） | `--gc-color-text-strong` | 页面标题、卡片标题和关键数据 |
| 正文文字 | Slate-600（`#475569`） | `--gc-color-text`、`--gc-color-text-muted` | 描述、字段值和辅助说明 |
| 弱化文字 | Slate-400（`#94A3B8`） | `--gc-color-text-soft` | 分类标签、占位说明和次要元数据 |
| 可信/正常 | Emerald-500 | `StatusTone: success` 及四件套变量 | 健康、可信、已完成和正常状态 |
| 即将到期/注意 | Amber-500 | `StatusTone: warning` 及四件套变量 | 到期提醒、待处理和风险提示 |
| 错误/不可信 | Rose-500 | `StatusTone: danger` 及四件套变量 | 已过期、失败、不可信和破坏性操作 |
| 信息 | Cyan/Info | `StatusTone: info` 及四件套变量 | 说明、检测中和中性提示 |

暗色主题不得简单反转亮色值。导航、表面、字段、遮罩、语义状态和图表都必须使用对应的暗色变量，并通过对比度检查。

### 8.2 容器、尺寸和层次

以下是示例的目标尺寸；正式代码通过现有或新增的稳定 `--gc-*` 令牌承载，禁止在页面组件中直接写入裸 `px`。

| 对象 | 视觉目标 | 规范要求 |
|---|---:|---|
| 左侧工作台导航 | 约 260px | 桌面稳定宽度，移动端转为可关闭抽屉 |
| 大容器/模态框 | 圆角约 16px | 使用大容器圆角令牌；Modal 需要独立的最大宽度约束 |
| 内部卡片 | 圆角约 12px | 统一卡片表面和轻边框，不叠套无意义容器 |
| 按钮/输入框 | 圆角约 8px | 同类控件保持一致高度和焦点环 |
| 圆形图标按钮/状态端点 | `999px` | 只用于圆形按钮、状态点、进度条端点和徽标 |
| 导航图标与文字 | 间距约 12px | 使用间距令牌，不在各菜单项重复定义 |
| 卡片阴影 | 极轻 | `--gc-shadow-sm` 或 `--gc-shadow-md` 配合语义边框 |
| Modal 阴影 | 明显悬浮 | `--gc-shadow-lg` 或 `--gc-shadow-overlay` 配合遮罩 |

Modal 的示例基线为最大宽度约 672px、横向内边距约 32px、纵向内边距约 24px；底部可以使用弱表面作为视觉收尾。具体尺寸必须由共享 `GcModal` 统一控制，不能由业务 View 各自覆盖。

### 8.3 按钮、标签和进度条

- Primary 按钮使用主色实心表面、清晰的 hover/pressed/disabled/loading 状态和可见焦点环；危险操作必须改用 `danger` 语义，不得只靠颜色区分。
- Secondary 按钮使用表面色、语义边框和轻微悬停阴影；Ghost/Icon 按钮默认不显示容器，悬停时显示弱表面。
- 当存在明确的熟悉图标时优先使用图标按钮；图标按钮必须提供 i18n ARIA 标签和 tooltip，不用文字胶囊替代图标。
- 权限门控按钮继续使用 `GcPermissionButton` 或其共享样式，业务页面不能重新实现权限判断。
- 状态标签统一使用 `StatusTone`，采用浅色背景/语义前景色/可选边框；示例中的 12px 加粗只是目标，正式字号使用字体令牌。
- 表单分类标签可以使用约 10px、全大写和宽字距；它只用于分类层级，不得把所有业务文案强制转换为大写。
- 进度条使用约 6-8px 的稳定高度、圆润端点和语义填充色；数值、状态和可访问名称必须由调用者传入，不能只用颜色表达进度。

### 8.4 卡片和模态框

- 卡片结构优先采用 Header / Body / Footer：Header 为图标加标题，右侧放状态；Body 展示核心指标、到期进度或风险信息；Footer 放主要动作和次要动作。
- 卡片的主要动作应保持明确的主次关系，主操作占据主要视觉权重，编辑、详情等辅助动作不得抢夺主操作焦点。
- 交互式选择卡默认使用较强边框和表面色；选中态使用主色边框和弱主色背景；悬停态只提升边框/表面，不改变业务状态。
- `GcModal` 必须支持遮罩、焦点捕获、Escape 关闭、关闭后焦点恢复、提交中禁用和错误反馈。遮罩可使用弱化背景配合共享模糊效果，但不允许在页面中复制一套 Modal。
- 模态框流程可以提供左上角圆形返回按钮；返回、关闭、取消和提交的含义必须通过 i18n 和可访问名称区分。
- 输入框使用字段表面、语义边框和焦点环；不能依赖示例的 Tailwind `ring-*` class，也不能移除键盘焦点。

### 8.5 排版、动效和实现边界

- 页面标题使用紧凑的强调层级；描述和元数据使用弱化文字；卡片中的核心数据优先展示并使用合适的状态语义。
- 示例的 `animate-in`、淡入和缩放只表示交互意图，正式实现使用共享 CSS 动效并尊重 `prefers-reduced-motion`，不能引入 Tailwind 运行时。
- 图标使用项目已有的本地图标入口或已批准的图标库；禁止 Font Awesome、Google Fonts、外部头像和 CDN 运行时依赖。
- 组件样式必须从语义令牌、设计系统组件和共享布局模式获得；页面不得复制颜色、圆角、阴影、按钮、标签或 Modal 规则。
- 这些规则只描述视觉与交互承载方式，不改变业务 API、权限、状态机、时间存储或国际化资源所有权。

## 九、检查清单

新建或修改前端组件时，确认以下事项：

- [ ] 无硬编码颜色值（`#xxx`、`rgb()`、`hsl()` 等）
- [ ] 颜色引用全部使用 `var(--gc-color-*)` 格式
- [ ] 间距使用 `var(--gc-space-*)`，不写裸 `px`
- [ ] 边框宽度使用 `var(--gc-border-width-default)`
- [ ] 圆角使用 `var(--gc-radius-*)`
- [ ] 阴影使用 `var(--gc-shadow-*)`
- [ ] 字号使用 `var(--gc-font-size-*)`
- [ ] 字体族使用 `var(--gc-font-family)`
- [ ] 不通过 `@media (prefers-color-scheme: dark)` 覆盖颜色
- [ ] 不新增 `--gc-color-legacy-*` 变量
- [ ] 可复用 UI 组件放入 `design-system/components/`
- [ ] 全局布局样式放入 `design-system/patterns/layout.css`
- [ ] Primary/Secondary/Ghost/Icon 按钮均有 hover、focus、disabled、loading 或危险态合同
- [ ] 卡片、交互选择卡、状态标签和进度条遵守 Header/Body/Footer 与 StatusTone 规则
- [ ] Modal 具备遮罩、焦点捕获、Escape、焦点恢复、提交中和错误状态
- [ ] 新增动效尊重 `prefers-reduced-motion`，且不引入 Tailwind 或外部 CDN
