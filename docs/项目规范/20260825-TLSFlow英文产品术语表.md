# TLSFlow 英文产品术语表

> 版本：1.0 | 更新日期：2026-08-25 | 适用范围：公开版前端英文界面（`en-US`）及其共享英文语言资源

## 一、品牌基线

- 公开产品品牌：`TLSFlow`
- 公开产品类别：`Certificate Lifecycle Management`
- 推荐完整描述：`TLSFlow — Certificate Lifecycle Management platform`
- 企业定制版品牌：`GCAC`，只在 `VITE_PRODUCT_EDITION=enterprise`、企业定制文案或内部协议中显示。
- `GCAC_*` 环境变量、`gcac.*` 协议、API 字段、数据库字段和 TypeScript 标识符属于内部兼容契约，不在本表中改名。

## 二、用户文案与内部模型

用户文案必须让海外 IT 运维人员一眼理解业务动作；内部模型名称只用于 API、审计、开发者诊断或明确标注的技术字段。

| 中文含义 | 用户文案（推荐） | 内部数据模型/协议 | 使用边界 |
|---|---|---|---|
| 证书生命周期管理平台 | Certificate lifecycle management platform | `certificate`, `certificateVersion`, `DeploymentPlan` | 首页、登录页、导航使用左列；协议和代码保留右列 |
| 证书管理 | Certificate lifecycle | `certificates` | 导航和页面标题使用左列 |
| 证书资产 | Certificate inventory | `certificateAsset` | 用户页面使用 inventory；API/审计字段可保留 asset |
| 应用资产 | Managed application | `applicationAsset`, `ServiceAsset` | 用户页面使用 managed application；ID 字段可显示为 Managed application ID |
| 应用关联 | Associate applications / Connected applications | `applicationAssetId`, binding | “关联”使用 associate；关联结果使用 connected |
| ACME 证书自动化 | ACME issuance and renewal | `acmeAutomation` | 页面标题使用左列，内部 key 不改 |
| CA 运维 | Certificate authority operations | `caOperations` | 页面标题使用左列 |
| 证书格式配置 | Certificate format configuration | `certificateFormatConfig` | 永远使用完整名 configuration，不使用 config |
| 证书交付格式 | Certificate delivery format | `artifactFormat`, `certificateArtifact` | 面向部署和输出选择时使用左列 |
| 资产中心 | Asset inventory | `assetCenter` | 导航使用左列 |
| 监控分析 | Monitoring analytics | `monitoringAnalysis` | 导航使用左列 |
| 日志审计 | Audit logs | `audit`, `auditLog` | 页面和导航使用 audit logs；事件列表使用 audit event list |
| 应用附件 | Connected applications | `applicationAttachments` | 禁止把 certificate 与 application 描述为 attachments |
| SSL 证书列表 | Certificate list | `sslCertificateList` | TLS 证书本身已经包含协议语境，列表标题不再加 SSL |
| 域名列表 | Certificate identity list | `domainList` | 列表同时承载 SAN、主体和证书版本时使用左列 |
| 开始/结束日期 | Valid from / Expires on | `notBefore` / `notAfter` | 证书有效期使用标准 PKI 术语 |
| 添加者 | Source | `sourceType`, `createdBy` | 证书来源可能是导入、ACME、CA 或 API，不只表示人 |
| 信任分发 | Trust-store distribution | `trustDistribution` | 涉及根证书或信任库分发时使用左列 |
| 信任视角 | Trust-store profile | `trustView` | TLS 检测中的根证书覆盖画像使用左列 |
| Pin SHA-256 | SPKI SHA-256 pin | `pinSha256` | 明确这是 Subject Public Key Info pin，避免误解为整张证书指纹 |
| 存活状态 | Connectivity | `liveness` | 设备列表和筛选器使用 connectivity |
| 控制版本 | Control-plane version | `controlVersion` | 设备管理面版本使用左列 |
| 类型 | Type | `kind` | 凭据列表使用 type，内部枚举 key 仍为 kind |

## 三、格式配置专用词

| 不推荐 | 推荐 | 说明 |
|---|---|---|
| config / configs | configuration / configurations | `config` 只允许出现在内部 key、协议字段或真实文件名中 |
| Artifact config | Certificate package configuration | 用户需要理解这是证书包的组成配置 |
| Certificate artifact format | Certificate delivery format | 用户关心交付目标和格式，不需要知道内部 artifact 名称 |
| Public certificate | Leaf certificate | 避免把 leaf certificate 与根证书、公开可见性混淆 |
| Extra chain file | Additional chain file | additional 比 extra 更适合正式运维界面 |
| Config file / Config path | Configuration file / Configuration path | 面向用户的字段统一使用完整单词 |

## 四、大小写规则

- 普通页面标题、导航、按钮、字段和帮助文案统一使用 sentence case：只首词和专有名词大写。
- 产品名、公司名、协议、算法、文件格式和标准保留官方大小写，例如 `TLSFlow`、`ACME`、`SNI`、`SPKI`、`SHA-256`、`PKCS#12`、`PFX`、`JKS`、`PEM`、`Nginx`、`IIS`。
- 不使用 Title Case 组合普通词，例如 `Certificate Format Config List`；应写为 `Certificate format configuration list`。
- sentence case 不改变内部 key、枚举值、API 字段或审计 action code。

## 五、原生英文审阅清单

每次新增或修改英文文案，按海外 IT 运维人员视角检查：

1. 页面标题是否直接说明对象或动作，而不是内部实现名。
2. 是否使用 PKI、TLS、ACME、CA 和部署领域的标准术语。
3. 是否把 application asset、artifact、config 等内部词泄露到普通用户流程。
4. 是否使用 sentence case，并保留专有名词和协议官方大小写。
5. 是否能在不阅读帮助文字的情况下理解下一步操作和风险。
