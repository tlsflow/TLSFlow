# 工作流 DSL 编写标准

## 适用范围

本文档定义 GCAC 项目当前支持的工作流 DSL 编写标准。该 DSL 是项目内领域协议，不是行业通用标准。任何生成、保存、校验、执行工作流 DSL 的代码，都必须以本文档和后端 schema 为准。

相关代码位置：

- 后端 DTO：`backend/src/modules/workflow-templates/dto/workflow-templates.dto.ts`
- 后端 schema：`backend/src/modules/workflow-templates/schema/workflow-templates.schema.ts`
- 后端运行时：`backend/src/modules/workflow-templates/domain/workflow-templates.domain-service.ts`
- 前端画布模型：`web/src/views/workflows/workflow-canvas.model.ts`
- 前端画布编辑器：`web/src/views/workflows/WorkflowCanvasEditor.vue`

## 文件模板来源

除数据库中的工作流模板/版本外，系统还支持把 `data/workflows` 目录中的 DSL 文件识别为“文件模板来源”。

规则如下：

- 扫描目录固定为项目根目录下的 `data/workflows`。
- 当前只识别 `.json` 和 `.dsl` 文件。
- 文件内容必须是合法的 `gcac.workflow/v1` JSON DSL。
- 扫描结果允许返回无效文件，但无效文件只能展示错误，不能用于创建或覆盖。
- 文件模板只是“来源”，不是另一套持久化模型。真正的工作流仍然落到数据库的 `workflow_templates` / `workflow_template_versions`。

前端动作约定：

- “从模板新建”：基于文件模板创建新的工作流草稿。
- “套用模板”：把文件模板内容应用到某个已有工作流，生成新的 draft version。

版本规则：

- 套用模板不会修改历史版本。
- 套用模板本质上是创建新的不可变版本。
- 套用到已有工作流时，目标工作流自己的稳定标识 `metadata.name` 必须保留，不能被文件模板的 `metadata.name` 覆盖。

## 顶层结构

```json
{
  "apiVersion": "gcac.workflow/v1",
  "kind": "CurlSshWorkflow",
  "metadata": {
    "name": "nginx-cert-update",
    "displayName": "Nginx 证书更新",
    "category": "certificate",
    "tags": ["nginx", "certificate"]
  },
  "variables": {},
  "steps": [],
  "rollback": []
}
```

字段要求：

- `apiVersion` 必须是 `gcac.workflow/v1`。
- `kind` 必须是 `CurlSshWorkflow`。
- `metadata.name` 必填，必须是稳定英文标识。
- `variables` 必填，用于声明运行时变量。
- `steps` 必填，必须是非空数组。
- `rollback` 可选，用于主流程失败后的回滚步骤。

## 导入与覆盖

前端工作流编辑器支持在 DSL 面板中直接导入 DSL JSON，或选择本地 DSL 文件覆盖当前画布草稿。

规则如下：

- 导入入口位于 `web/src/views/workflows/WorkflowCanvasEditor.vue` 的 DSL 面板。
- 导入动作只覆盖浏览器中的当前画布草稿，不会自动保存到后端。
- 导入完成后，必须显式点击“保存草稿”，才会创建新的工作流版本。
- 导入 DSL 时，顶层结构必须满足：
  - `apiVersion = gcac.workflow/v1`
  - `kind = CurlSshWorkflow`
  - `metadata` 为对象
  - `variables` 为对象
  - `steps` 为非空数组
- 当前画布会把 DSL 转成纵向阶段流程图，并自动重新排列节点。

兼容说明：

- 画布当前主要可视化编辑主流程节点、阶段、变量和常用节点字段。
- 对于画布暂未直接暴露的高级字段，例如：
  - `http.request.headers`
  - `retry`
  - `extract`
  - 高级 `assert`
  - 自定义 `rollback`
- 导入时前端会尽量保留这些字段，并在再次保存 DSL 时原样回写，避免因为“导入一次”而静默丢字段。
- 但如果用户在画布中把对应节点类型改掉，或删除原节点，这些透传字段也会随之丢失。这是当前版本的已知边界。

## 阶段规范

每个 step 可以声明 `stage`：

```json
{
  "name": "reload_nginx",
  "type": "ssh",
  "stage": "refresh"
}
```

支持的阶段：

| stage | 中文名 | 用途 |
| --- | --- | --- |
| `prepare` | 准备 | SSH 认证登录、CURL 认证、凭据获取、前置上下文准备 |
| `backup` | 备份 | 保存变更前状态、生成回滚材料 |
| `install` | 安装 | 上传、写入或替换证书/配置/文件 |
| `refresh` | 刷新 | 重载服务、刷新缓存、触发生效 |
| `verify` | 验证 | 检查 HTTP 状态、证书指纹、服务状态、人工验收 |

执行规则：

- 只要 `steps` 中任一 step 声明了 `stage`，后端按固定阶段顺序执行：`prepare` → `backup` → `install` → `refresh` → `verify`。
- 同一阶段内保持原始数组顺序。
- 没有声明 `stage` 的旧模板保持原始数组顺序，保证兼容。
- 新增 DSL 必须显式声明 `stage`。

## 变量规范

变量定义写在 `variables` 中：

```json
{
  "deviceHost": {
    "type": "string",
    "required": true,
    "description": "目标主机"
  },
  "sshUsername": {
    "type": "string",
    "required": true,
    "description": "SSH 用户名"
  },
  "certificate": {
    "type": "certificate",
    "required": true,
    "sensitive": true,
    "description": "证书材料"
  },
  "credential": {
    "type": "secret",
    "required": true,
    "sensitive": true,
    "description": "凭据 SecretRef"
  }
}
```

支持的变量类型：

- `string`
- `number`
- `boolean`
- `enum`
- `object`
- `file`
- `secret`
- `certificate`

变量引用格式：

```text
{{deviceHost}}
{{sshUsername}}
{{certificate.pem}}
{{steps.login.output.body.token}}
```

规则：

- 变量名必须是英文标识符：`^[a-zA-Z][a-zA-Z0-9_]*$`。
- 引用变量前必须先在 `variables` 中声明，或由上游 extractor 产出。
- `secret` 类型不能提供 `default`。
- `certificate` 和 `secret` 默认视为敏感变量。
- 禁止把密码、token、私钥、PFX 明文写进 DSL。

## SecretRef 规范

Secret 只能通过 `secret://...` 引用：

```json
{
  "credentialSecretRef": "secret://workflow/ssh"
}
```

常用引用：

- `secret://workflow/ssh`：SSH 凭据。
- `secret://workflow/device-api`：设备 API token 或认证凭据。
- `secret://cert/key`：证书私钥。
- `secret://ca/root`：CA 证书。

禁止写法：

```json
{
  "password": "plain-text-password",
  "privateKey": "-----BEGIN PRIVATE KEY-----..."
}
```

## HTTP/CURL Step

HTTP step 用于认证、调用接口、获取 token、验证状态等。

```json
{
  "name": "prepare_auth",
  "type": "http",
  "stage": "prepare",
  "request": {
    "method": "POST",
    "url": "https://{{deviceHost}}/api/login",
    "auth": {
      "type": "bearer",
      "secretRef": "secret://workflow/device-api"
    },
    "timeoutSeconds": 30
  },
  "extract": [
    {
      "name": "accessToken",
      "type": "jsonPath",
      "path": "$.token",
      "sensitive": true
    }
  ],
  "assert": [
    {
      "type": "statusCode",
      "equals": 200
    }
  ]
}
```

`request` 支持：

- `method`: `GET`、`POST`、`PUT`、`PATCH`、`DELETE`
- `url`
- `query`
- `headers`
- `headerRefs`
- `bodyType`: `json`、`form`、`multipart`、`raw`、`none`
- `body`
- `form`
- `multipart`
- `auth`
- `tls`
- `timeoutSeconds`
- `maxResponseBytes`
- `successStatusCodes`
- `failOnNon2xx`

HTTP auth 支持：

- `none`
- `basic`
- `bearer`
- `api_key`
- `cookie`
- `custom_header`
- `mtls`

## SSH Step

SSH step 用于远端命令、脚本、服务重载、文件操作等。

单命令：

```json
{
  "name": "test_nginx",
  "type": "ssh",
  "stage": "refresh",
  "ssh": {
    "mode": "command",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "command": "nginx -t",
    "timeoutSeconds": 60
  }
}
```

多命令：

```json
{
  "name": "reload_nginx",
  "type": "ssh",
  "stage": "refresh",
  "ssh": {
    "mode": "command",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "commands": [
      "nginx -t",
      "systemctl reload nginx",
      "systemctl status nginx --no-pager"
    ],
    "timeoutSeconds": 120
  },
  "assert": [
    {
      "type": "regex",
      "pattern": ".*"
    }
  ]
}
```

执行规则：

- 一个 SSH step 对应一次 SSH 会话。
- `commands` 中的命令在同一个 SSH 会话中按数组顺序执行。
- 任一命令失败后停止后续命令。
- 结果会聚合 stdout、stderr，并保留每条命令的执行结果。
- `credentialSecretRef` 必须是 SecretRef。

`mode` 支持：

- `command`
- `script`
- `interactive`

当前推荐优先使用 `command` + `commands` 表达多个简单命令。

安全边界：

- 禁止把证书私钥、PFX 密码、token 等敏感内容内联到 `ssh.command`、`ssh.commands` 或 `ssh.script`。
- 需要上传证书或私钥文件时，必须使用正式 `sftp` 或 `scp` step，不能用 `cat <<EOF`、`echo`、`printf` 等 SSH 命令拼接文件内容。
- SSH 命令适合执行 `nginx -t`、`apache2ctl -t`、`systemctl reload ...` 这类远端动作，不适合承载文件传输内容。

前端画布导入规则：

- `ssh.command`、`ssh.commands`、`ssh.script` 都会映射到属性面板中的“命令”文本框。
- `ssh.commands` 导入时会按换行拼接显示，保存时仍按多行命令转回 `commands` 数组。
- `ssh.script` 导入时会完整显示脚本内容，保存时必须继续回写为 `mode: "script"` + `script`，不能降级成空 `command`。
- 导入 DSL 时，节点标题优先使用 step 的 `name`，避免复杂模板在画布上全部显示成泛化的“SSH 命令”。

## SFTP/SCP Step

SFTP/SCP step 用于正式文件传输。证书、公钥、私钥、配置片段等文件上传必须放在 `install` 阶段。

SFTP 上传证书：

```json
{
  "name": "install_certificate_pem",
  "type": "sftp",
  "stage": "install",
  "sftp": {
    "direction": "upload",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "remotePath": "/etc/nginx/cert.pem",
    "contentRef": "{{certificate.pem}}",
    "mode": "0644",
    "timeoutSeconds": 60
  },
  "extract": [
    {
      "name": "certificateUploadHash",
      "type": "jsonPath",
      "path": "$.transferResults[0].hash",
      "optional": true
    }
  ]
}
```

SCP 上传私钥：

```json
{
  "name": "install_certificate_key",
  "type": "scp",
  "stage": "install",
  "scp": {
    "direction": "upload",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "remotePath": "/etc/nginx/key.pem",
    "contentRef": "{{certificate.privateKey}}",
    "mode": "0600",
    "timeoutSeconds": 60
  }
}
```

`sftp` / `scp` 字段支持：

- `direction`: `upload` 或 `download`，必填。
- `connection`: SSH 连接对象，字段与 SSH step 的 `ssh.connection` 一致，必填。
- `remotePath`: 远端路径，必填。
- `contentRef`: 上传内容引用，可写 `{{certificate.pem}}`、`{{certificate.privateKey}}` 等变量表达式。
- `contentEncoding`: `utf8` 或 `base64`，默认按 UTF-8 文本处理。
- `localPath`: 本地路径或虚拟产物路径；上传时可与 `contentRef` 二选一，下载时必填。
- `temporaryPath`: 临时上传路径，用于原子替换。
- `expectedHash`: 期望 SHA-256 hex。
- `expectedSize`: 期望字节数，必须是非负整数。
- `verifyHash`: 是否校验传输后 hash。
- `mode`: 远端文件权限，例如 `0644`、`0600`。
- `owner` / `group`: 远端 owner/group。
- `timeoutSeconds`: 正整数超时秒数。

校验规则：

- `upload` 至少必须提供 `contentRef` 或 `localPath`。
- `download` 必须提供 `localPath`。
- `connection.credentialSecretRef` 必须是 SecretRef。
- 文件传输通道允许承载 `certificate.privateKey` 等敏感内容，但运行计划、日志和返回 detail 必须脱敏展示。
- 如果 SFTP 可用，优先使用 `sftp`；只有明确需要 SCP 协议或目标不支持 SFTP 时，才使用 `scp`。

## Condition Step

Condition step 用于判断变量或上游输出。

```json
{
  "name": "is_linux",
  "type": "condition",
  "stage": "prepare",
  "condition": {
    "variable": "deviceOs",
    "equals": "linux"
  },
  "description": "只允许 Linux 目标继续"
}
```

支持的判断操作：

- `equals`
- `notEquals`
- `exists`

规则：

- `variable` 必填。
- `equals`、`notEquals`、`exists` 必须且只能出现一个。

## Wait Step

```json
{
  "name": "wait_apply",
  "type": "wait",
  "stage": "refresh",
  "seconds": 10
}
```

```json
{
  "name": "manual_verify",
  "type": "manual",
  "stage": "verify",
  "instruction": "请人工确认目标服务证书已更新。"
}
```

## Extractor 规范

Extractor 用于从 step 输出中提取变量。

数组写法：

```json
{
  "extract": [
    {
      "name": "remoteFingerprint",
      "type": "jsonPath",
      "path": "$.fingerprint"
    }
  ]
}
```

对象写法：

```json
{
  "extract": {
    "remoteFingerprint": {
      "type": "jsonPath",
      "path": "$.fingerprint"
    }
  }
}
```

支持类型：

- `jsonPath`
- `header`
- `regex`
- `statusCode`
- `textContains`

提取出的变量可在后续 step 中通过 `{{remoteFingerprint}}` 引用。

## Assert 规范

Assert 用于判断 step 是否成功。

```json
{
  "assert": [
    {
      "type": "statusCode",
      "equals": 200
    },
    {
      "type": "certificateFingerprint",
      "actual": "{{remoteFingerprint}}",
      "expected": "{{certificate.fingerprintSha256}}"
    }
  ]
}
```

支持类型：

- `statusCode`
- `jsonPath`
- `header`
- `contains`
- `regex`
- `certificateFingerprint`

## Rollback 规范

`rollback` 是失败后执行的回滚步骤。

```json
{
  "rollback": [
    {
      "name": "restore_old_cert",
      "type": "ssh",
      "stage": "install",
      "ssh": {
        "mode": "command",
        "connection": {
          "host": "{{deviceHost}}",
          "username": "{{sshUsername}}",
          "credentialSecretRef": "secret://workflow/ssh",
          "hostKeyPolicy": "manual_approval_required"
        },
        "commands": [
          "cp /etc/nginx/cert.pem.bak /etc/nginx/cert.pem",
          "nginx -t",
          "systemctl reload nginx"
        ],
        "timeoutSeconds": 120
      }
    }
  ]
}
```

要求：

- 回滚步骤也必须避免明文 Secret。
- 回滚步骤应尽量可幂等。
- 回滚步骤应优先使用已有备份材料。

## 禁止事项

- 禁止把密码、token、私钥、PFX 密码明文写入 DSL。
- 禁止把证书或私钥内容塞进 `ssh.command` / `ssh.commands` / `ssh.script`；上传文件必须使用 `sftp` 或 `scp` step。
- 禁止引用未声明变量。
- 禁止新增 DSL 时省略 `stage`。
- 禁止把多个业务动作塞进一个不可读的大脚本，除非必须保持远端事务性。
- 禁止在前端绕过统一画布模型手写另一套 DSL 生成逻辑。
- 禁止修改后端 schema 后不更新本文档。

## 变更同步要求

修改以下内容时必须同步更新本文档：

- `WorkflowDslV1`
- `WorkflowStep`
- `WorkflowVariableDefinition`
- step 类型、字段、校验规则
- stage 阶段定义或执行顺序
- SecretRef 规则
- SSH/CURL 执行器适配规则
- 前端画布到 DSL 的转换规则
