# 工作流 DSL 编写标准

## 适用范围

本文档定义 GCAC 项目当前支持的工作流 DSL 编写标准。该 DSL 是项目内领域协议，不是行业通用标准。任何生成、保存、校验、执行工作流 DSL 的代码，都必须以本文档和后端 schema 为准。

相关代码位置：

- 后端 DTO：`backend/src/modules/workflow-templates/dto/workflow-templates.dto.ts`
- 后端 schema：`backend/src/modules/workflow-templates/schema/workflow-templates.schema.ts`
- 后端运行时：`backend/src/modules/workflow-templates/domain/workflow-templates.domain-service.ts`
- 前端画布模型：`web/src/views/workflows/workflow-canvas.model.ts`
- 前端画布编辑器：`web/src/views/workflows/WorkflowCanvasEditor.vue`

## 顶层结构

```json
{
  "apiVersion": "gcac.workflow/v1",
  "kind": "CurlSshWorkflow",
  "metadata": {
    "name": "nginx-cert-update",
    "displayName": "Nginx 证书更新",
    "category": "certificate",
    "tags": ["nginx", "certificate"]
  },
  "variables": {},
  "steps": [],
  "rollback": []
}
```

字段要求：

- `apiVersion` 必须是 `gcac.workflow/v1`。
- `kind` 必须是 `CurlSshWorkflow`。
- `metadata.name` 必填，必须是稳定英文标识。
- `variables` 必填，用于声明运行时变量。
- `steps` 必填，必须是非空数组。
- `rollback` 可选，用于主流程失败后的回滚步骤。

## 阶段规范

每个 step 可以声明 `stage`：

```json
{
  "name": "reload_nginx",
  "type": "ssh",
  "stage": "refresh"
}
```

支持的阶段：

| stage | 中文名 | 用途 |
| --- | --- | --- |
| `prepare` | 准备 | SSH 认证登录、CURL 认证、凭据获取、前置上下文准备 |
| `backup` | 备份 | 保存变更前状态、生成回滚材料 |
| `install` | 安装 | 上传、写入或替换证书/配置/文件 |
| `refresh` | 刷新 | 重载服务、刷新缓存、触发生效 |
| `verify` | 验证 | 检查 HTTP 状态、证书指纹、服务状态、人工验收 |

执行规则：

- 只要 `steps` 中任一 step 声明了 `stage`，后端按固定阶段顺序执行：`prepare` → `backup` → `install` → `refresh` → `verify`。
- 同一阶段内保持原始数组顺序。
- 没有声明 `stage` 的旧模板保持原始数组顺序，保证兼容。
- 新增 DSL 必须显式声明 `stage`。

## 变量规范

变量定义写在 `variables` 中：

```json
{
  "deviceHost": {
    "type": "string",
    "required": true,
    "description": "目标主机"
  },
  "sshUsername": {
    "type": "string",
    "required": true,
    "description": "SSH 用户名"
  },
  "certificate": {
    "type": "certificate",
    "required": true,
    "sensitive": true,
    "description": "证书材料"
  },
  "credential": {
    "type": "secret",
    "required": true,
    "sensitive": true,
    "description": "凭据 SecretRef"
  }
}
```

支持的变量类型：

- `string`
- `number`
- `boolean`
- `enum`
- `object`
- `file`
- `secret`
- `certificate`

变量引用格式：

```text
{{deviceHost}}
{{sshUsername}}
{{certificate.pem}}
{{steps.login.output.body.token}}
```

规则：

- 变量名必须是英文标识符：`^[a-zA-Z][a-zA-Z0-9_]*$`。
- 引用变量前必须先在 `variables` 中声明，或由上游 extractor 产出。
- `secret` 类型不能提供 `default`。
- `certificate` 和 `secret` 默认视为敏感变量。
- 禁止把密码、token、私钥、PFX 明文写进 DSL。

## SecretRef 规范

Secret 只能通过 `secret://...` 引用：

```json
{
  "credentialSecretRef": "secret://workflow/ssh"
}
```

常用引用：

- `secret://workflow/ssh`：SSH 凭据。
- `secret://workflow/device-api`：设备 API token 或认证凭据。
- `secret://cert/key`：证书私钥。
- `secret://ca/root`：CA 证书。

禁止写法：

```json
{
  "password": "plain-text-password",
  "privateKey": "-----BEGIN PRIVATE KEY-----..."
}
```

## HTTP/CURL Step

HTTP step 用于认证、调用接口、获取 token、验证状态等。

```json
{
  "name": "prepare_auth",
  "type": "http",
  "stage": "prepare",
  "request": {
    "method": "POST",
    "url": "https://{{deviceHost}}/api/login",
    "auth": {
      "type": "bearer",
      "secretRef": "secret://workflow/device-api"
    },
    "timeoutSeconds": 30
  },
  "extract": [
    {
      "name": "accessToken",
      "type": "jsonPath",
      "path": "$.token",
      "sensitive": true
    }
  ],
  "assert": [
    {
      "type": "statusCode",
      "equals": 200
    }
  ]
}
```

`request` 支持：

- `method`: `GET`、`POST`、`PUT`、`PATCH`、`DELETE`
- `url`
- `query`
- `headers`
- `headerRefs`
- `bodyType`: `json`、`form`、`multipart`、`raw`、`none`
- `body`
- `form`
- `multipart`
- `auth`
- `tls`
- `timeoutSeconds`
- `maxResponseBytes`
- `successStatusCodes`
- `failOnNon2xx`

HTTP auth 支持：

- `none`
- `basic`
- `bearer`
- `api_key`
- `cookie`
- `custom_header`
- `mtls`

## SSH Step

SSH step 用于远端命令、脚本、服务重载、文件操作等。

单命令：

```json
{
  "name": "test_nginx",
  "type": "ssh",
  "stage": "refresh",
  "ssh": {
    "mode": "command",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "command": "nginx -t",
    "timeoutSeconds": 60
  }
}
```

多命令：

```json
{
  "name": "reload_nginx",
  "type": "ssh",
  "stage": "refresh",
  "ssh": {
    "mode": "command",
    "connection": {
      "host": "{{deviceHost}}",
      "username": "{{sshUsername}}",
      "credentialSecretRef": "secret://workflow/ssh",
      "hostKeyPolicy": "manual_approval_required"
    },
    "commands": [
      "nginx -t",
      "systemctl reload nginx",
      "systemctl status nginx --no-pager"
    ],
    "timeoutSeconds": 120
  },
  "assert": [
    {
      "type": "regex",
      "pattern": ".*"
    }
  ]
}
```

执行规则：

- 一个 SSH step 对应一次 SSH 会话。
- `commands` 中的命令在同一个 SSH 会话中按数组顺序执行。
- 任一命令失败后停止后续命令。
- 结果会聚合 stdout、stderr，并保留每条命令的执行结果。
- `credentialSecretRef` 必须是 SecretRef。

`mode` 支持：

- `command`
- `script`
- `interactive`

当前推荐优先使用 `command` + `commands` 表达多个简单命令。

## Condition Step

Condition step 用于判断变量或上游输出。

```json
{
  "name": "is_linux",
  "type": "condition",
  "stage": "prepare",
  "condition": {
    "variable": "deviceOs",
    "equals": "linux"
  },
  "description": "只允许 Linux 目标继续"
}
```

支持的判断操作：

- `equals`
- `notEquals`
- `exists`

规则：

- `variable` 必填。
- `equals`、`notEquals`、`exists` 必须且只能出现一个。

## Wait Step

```json
{
  "name": "wait_apply",
  "type": "wait",
  "stage": "refresh",
  "seconds": 10
}
```

## Manual Step

```json
{
  "name": "manual_verify",
  "type": "manual",
  "stage": "verify",
  "instruction": "请人工确认目标服务证书已更新。"
}
```

## Extractor 规范

Extractor 用于从 step 输出中提取变量。

数组写法：

```json
{
  "extract": [
    {
      "name": "remoteFingerprint",
      "type": "jsonPath",
      "path": "$.fingerprint"
    }
  ]
}
```

对象写法：

```json
{
  "extract": {
    "remoteFingerprint": {
      "type": "jsonPath",
      "path": "$.fingerprint"
    }
  }
}
```

支持类型：

- `jsonPath`
- `header`
- `regex`
- `statusCode`
- `textContains`

提取出的变量可在后续 step 中通过 `{{remoteFingerprint}}` 引用。

## Assert 规范

Assert 用于判断 step 是否成功。

```json
{
  "assert": [
    {
      "type": "statusCode",
      "equals": 200
    },
    {
      "type": "certificateFingerprint",
      "actual": "{{remoteFingerprint}}",
      "expected": "{{certificate.fingerprintSha256}}"
    }
  ]
}
```

支持类型：

- `statusCode`
- `jsonPath`
- `header`
- `contains`
- `regex`
- `certificateFingerprint`

## Rollback 规范

`rollback` 是失败后执行的回滚步骤。

```json
{
  "rollback": [
    {
      "name": "restore_old_cert",
      "type": "ssh",
      "stage": "install",
      "ssh": {
        "mode": "command",
        "connection": {
          "host": "{{deviceHost}}",
          "username": "{{sshUsername}}",
          "credentialSecretRef": "secret://workflow/ssh",
          "hostKeyPolicy": "manual_approval_required"
        },
        "commands": [
          "cp /etc/nginx/cert.pem.bak /etc/nginx/cert.pem",
          "nginx -t",
          "systemctl reload nginx"
        ],
        "timeoutSeconds": 120
      }
    }
  ]
}
```

要求：

- 回滚步骤也必须避免明文 Secret。
- 回滚步骤应尽量可幂等。
- 回滚步骤应优先使用已有备份材料。

## 完整示例

```json
{
  "apiVersion": "gcac.workflow/v1",
  "kind": "CurlSshWorkflow",
  "metadata": {

      "name": "prepare_auth",
      "type": "http",

      "stage": "backup",
      "ssh": {
        "mode": "command",
        "connection": {

          "username": "{{sshUsername}}",
          "credentialSecretRef": "secret://workflow/ssh",

    },

        },

          "systemctl reload nginx"

        "timeoutSeconds": 120
      },
      "assert": [
        {
          "type": "regex",
          "pattern": ".*"
        }
      ]
    },
    {
      "name": "verify_http",
      "type": "http",
      "stage": "verify",
      "request": {
        "method": "GET",
        "url": "{{verifyUrl}}",
        "timeoutSeconds": 30
      },
      "assert": [
        {
          "type": "statusCode",
          "equals": 200
        }
      ]
    }
  ],
  "rollback": [
    {
      "name": "restore_cert",
      "type": "ssh",
      "stage": "install",
      "ssh": {
        "mode": "command",
        "connection": {
          "host": "{{deviceHost}}",
```

## 禁止事项

- 禁止把密码、token、私钥、PFX 密码明文写入 DSL。
- 禁止引用未声明变量。
- 禁止新增 DSL 时省略 `stage`。
- 禁止把多个业务动作塞进一个不可读的大脚本，除非必须保持远端事务性。
- 禁止在前端绕过统一画布模型手写另一套 DSL 生成逻辑。
- 禁止修改后端 schema 后不更新本文档。

## 变更同步要求

修改以下内容时必须同步更新本文档：

- `WorkflowDslV1`
- `WorkflowStep`
- `WorkflowVariableDefinition`
- step 类型、字段、校验规则
- stage 阶段定义或执行顺序
- SecretRef 规则
- SSH/CURL 执行器适配规则
- 前端画布到 DSL 的转换规则
