# Agent 原子操作插件规范

## 1. 目标

Agent 原子操作插件用于处理 IIS、NGINX、Apache 等内置 Handler 无法覆盖的证书部署场景。控制面负责选择插件、绑定变量和签发计划；Windows/Linux Agent 只负责校验并执行受控原子操作，不为每个产品增加分支。

## 2. 数据边界

- 插件包：`gcac.agent-plugin/v1` Manifest、包哈希、签名状态、权限审批状态和安装状态。
- Agent 挂载：固定 Agent、插件包版本、兼容性快照和权限快照。
- 应用资产绑定：`mode=PLUGIN`、挂载 ID、插件版本、普通变量、SecretRef 和证书 Artifact 输出映射。
- 执行计划：`gcac.agent-plan/v1`、运行/步骤 ID、目标 Agent、插件哈希、过期时间、幂等键、权限、操作、回滚和 HMAC 签名。

现有 `mode=NATIVE_HANDLER` 行为保持不变；缺失 `mode` 时按原生模式处理，避免破坏历史资产。

## 3. 原子操作

第一版只允许：

- `preflight.assert`
- `file.backup`
- `file.atomic_replace`
- `file.restore`
- `file.set_permissions`
- `command.execute`
- `service.control`
- `tls.verify`

阶段顺序为 `prepare → backup → install → refresh → verify`，回滚操作使用 `rollback`。包含文件替换、权限修改、命令或服务控制的插件必须声明回滚。

## 4. 安全规则

1. 插件声明的平台、架构、Agent Capability 和原子操作 Schema 必须与目标 Agent 匹配。
2. 高风险权限必须审批后才能启用；挂载时再次检查安装状态和兼容性。
3. 文件、程序、服务和网络目标在变量展开后再次进行权限校验。
4. `command.execute` 只接受 `program + args`，禁止 Shell、命令拼接和隐式解释器。
5. SecretRef 只保存引用标识，不得写入插件文件、应用资产日志或文档。
6. 签名计划绑定租户、Agent、运行、步骤、插件哈希和过期时间；Agent 使用常量时间比较校验 HMAC。
7. Agent 使用幂等账本记录已完成操作、备份和回滚结果；回滚失败必须返回 `MANUAL_INTERVENTION`。

## 5. 证书 Artifact

插件通过 `artifactInputs` 声明证书、私钥、证书链、Bundle 或普通文件。应用资产为每个输入选择证书格式，并使用 `slot=outputKey` 映射导出文件。控制面生成实际证书材料后再编译执行计划，插件不得读取控制面文件路径。

## 6. 内置插件

首批内置 Manifest 位于 `backend/src/modules/plugins/builtin-agent-plugins/`：

- RabbitMQ PEM 证书和私钥替换。
- Java PKCS#12 / KeyStore 文件替换。
- 自定义 Windows Service 证书文件替换。

这些插件与用户插件使用同一校验、审批、挂载、资产绑定和执行链路，不允许特殊旁路。

用户导入的 Agent 插件保存到 `data/agent-plugins/`。用户工作流 DSL 继续保存到 `data/workflows/`。两类协议必须使用独立目录、独立 Schema 和独立加载器，禁止跨目录扫描或按文件内容猜测协议类型。

## 7. 故障排查

- `PLUGIN_PERMISSION_DENIED`：检查插件是否启用、高风险权限是否审批，以及展开后的路径/程序/服务/网络目标是否在声明范围内。
- `AGENT_PLUGIN_MOUNT_INCOMPATIBLE`：检查 Agent 平台、架构、在线状态和 `agent.atomic_plan.execute` Capability。
- `AGENT_PLAN_SIGNATURE_INVALID`：检查控制面与 Agent 的 `GCAC_AGENT_PLAN_SIGNING_KEY` 是否一致，计划是否被修改，目标 Agent 是否匹配。
- `AGENT_PLAN_EXPIRED`：检查控制面与宿主时间同步后重新派发。
- `AGENT_ROLLBACK_FAILED`：读取 Agent 原子计划账本和操作结果，按 `MANUAL_INTERVENTION` 处理，不得自动重复覆盖现场。
