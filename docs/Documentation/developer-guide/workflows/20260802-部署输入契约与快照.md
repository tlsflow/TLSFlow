# 部署输入契约与快照

## Contract 是唯一输入声明位置

工作流和 Agent Plugin 共享 `DeploymentInputContractV1`。Contract 只声明四类槽位：

| 槽位 | 内容 | 典型用途 |
| --- | --- | --- |
| `variables` | 普通变量 | 服务名、路径、端口、目标标识 |
| `connections` | HTTP/SSH 连接字段 | Host、Port、用户名、TLS 或 Host Key |
| `credentials` | Credential Slot | 用户名密码、SSH Key、Bearer Token、API Key、客户端证书 |
| `artifacts` | Artifact Slot | 叶子证书、私钥、中间链、PFX 或其他文件 |

普通变量类型不包含 `credential` 和 `certificate`。证书材料只能通过 Artifact Slot 进入执行器，不能写入普通变量、DSL 命令、日志或计划 JSON。

## Source、生命周期和覆盖策略

普通变量和连接字段必须明确声明：

- `source`：`asset`、`binding`、`default`、`derived`、`system` 或 `step_output`。
- `lifecycle`：`pre_execution`、`runtime_injected` 或 `step_output`。
- `bindingPolicy`：`fixed`、`default_overridable` 或 `required_binding`。
- `configurationMode`：`required`、`advanced` 或 `runtime`。

有效值按执行覆盖、应用资产、受管目标、设备资产、插件默认值的层级解析，但 `asset` 来源优先表达已发现事实。默认值不能伪装成发现结果；`fixed` 字段不能被执行覆盖。

## 统一解析结果

运行时只接受 `ResolvedDeploymentInputV1`，必须包含：

```text
assetContext
variables
connections
credentials
artifacts
provenance
sensitivePaths
issues
executable
resolvedSha256
```

解析器按 Contract、标准 Asset Context、Effective Binding、Credential Snapshot、Artifact Snapshot 和执行覆盖生成结果。`executable=false` 或存在阻断 Issue 时，必须在进入 DSL Step、Agent、Gateway、SSH 或 HTTP 之前失败关闭。

解析阶段：

| 阶段 | 作用 |
| --- | --- |
| `configure` | 展示表单和问题，不执行外部动作 |
| `save` | 保存绑定，复用生产解析器 |
| `preflight` | 创建或更新计划、生成预检和快照 |
| `execute` | 使用固定身份和运行时注入值执行 |

在没有运行时注入值和 Step 输出的前提下，`preflight` 和 `execute` 的 `resolvedSha256` 必须一致。执行器不得自行重新合并旧的 `userVariables`、`assetVariables` 或平行 Credential 字段。

## Credential 与 Artifact

Credential 绑定只保存稳定 `credentialId`。计划阶段固定 Credential 版本和脱敏快照，运行时由 Secret Grant 解析精确 SecretRef；日志、审计、错误和数据库快照不得保存明文。

Artifact 绑定只保存 Artifact 身份、输出槽位、摘要和敏感标记。私钥、PFX 密码和 PFX 内容只在受控 Artifact Grant 中短暂可用，用后立即回收。

## 快照和复核

`DeploymentInputSnapshotV1` 是计划的不可变输入依据，包含：

- 执行身份：Assignment、PluginVersion、PluginBinding、WorkflowVersion 或 WorkflowExecutionBinding。
- 脱敏后的 Asset Context、变量、连接、凭据和制品结构。
- 每个值的 Provenance、敏感路径、Issue、`executable` 和 `resolvedSha256`。
- Snapshot ID、revision 和哈希引用。

执行重试必须验证 Snapshot ID、目标身份和哈希一致，不能回查“当前最新配置”改变已批准计划。`configFingerprint` 会进入证书位置和输入快照；执行前重新读取并比对的门禁在当前实现中仍是 `TODO`，不能在插件文档中宣称已经完成。
