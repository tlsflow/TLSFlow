# 工作流执行器、恢复与回滚

## Step 和阶段

当前 Step 类型包括：

`http`、`ssh`、`sftp`、`scp`、`condition`、`transform`、`foreach`、`checkpoint`、`checkpoint_verify`、`wait` 和 `manual`。

证书部署阶段固定为：

```text
prepare -> backup -> install -> refresh -> verify
```

`stage` 是计划和审计中的业务阶段，不是新的 Step 类型。`rollback` 是同一 WorkflowVersion 的独立数组，不能把回滚步骤拼接到主流程末尾，也不能维护第二份 DSL。

## HTTP/CURL

HTTP Step 必须通过 Contract 中声明的 `connectionRef` 获取连接。认证使用 Credential 或 SecretRef：

- Basic、Bearer、API Key、Cookie、Custom Header 和 mTLS 必须使用受控 Secret。
- `extract` 可提取 JSON Path、响应路径、Header、正则、状态码或文本包含结果。
- `assert` 可检查状态码、JSON Path、Header、文本、正则和证书指纹。
- URL 只允许 HTTP(S)，默认拒绝非本地明文 HTTP。
- `tls.verify=false` 只有在 `allowInsecure=true` 且经过审批、审计、隔离测试和发布门禁时才可使用。

CURL 执行器负责请求重试、幂等键、响应大小限制、脱敏和结构化错误；模板不能把 Secret 直接写入 Header、Body、Query 或普通变量。

## SSH、SFTP 和 SCP

SSH Command Step 使用 `connectionRef` 和 Credential Slot。Host Key 策略必须明确为严格校验、首次信任或人工审批；部署和回滚不能通过猜测目标平台跳过 Host Key 门禁。

SFTP/SCP 文件传输使用 Artifact 或受控内容引用。上传应优先写入临时路径，校验大小或哈希后再原子替换；下载必须有 LocalFileStore。文件权限、Owner、Group、远程路径、期望哈希和超时都必须进入计划和审计。

命令执行结果只能返回脱敏日志、状态和结构化错误。脚本、私钥、密码和证书材料不能进入模板文本或普通日志。

## extract、assert 和 foreach

- `extract` 产生后续上下文可引用的 Step 输出；敏感提取值必须标记敏感并脱敏。
- `assert` 失败必须阻止当前阶段伪成功，并保留断言类型、结果和错误摘要。
- `foreach` 必须声明 `itemsPath`、元素变量和子步骤；`maxItems` 最大为 1000，嵌套最多三层。
- 只读发现可以使用 `continueOnError` 保留部分结果；部署、变更和回滚禁止使用该选项。
- 每个子项必须有独立执行身份和幂等键，不能因 Step 名相同而把不同目标当成重复请求。

## checkpoint 和恢复账本

`checkpoint` 必须声明名称、捕获路径和 `requiredForRollback`，可选规范化哈希；`checkpoint_verify` 用实际值和期望哈希验证漂移。

正式执行开始前，宿主创建恢复账本、资源锁和必要的 Execution Grant。每个成功 Step 写入账本，资源 Grant 在 Step 结束后回收。只有幂等步骤允许自动恢复；非幂等运行中步骤必须转人工处理或显式补偿。

恢复和回滚必须：

1. 使用原计划固定的 WorkflowVersion 和输入快照。
2. 先验证 checkpoint、设备版本和资源锁。
3. 按声明的 rollback 数组执行，不临时拼接命令。
4. 同时保留原始失败、回滚结果和最终验证结果。

## 当前成熟度边界

SSH/SFTP/SCP/CURL 的结构化执行器和工作流测试已有代码证据；Windows Remote 仍有 planning/mock 边界，不能在工作流页面上写成真实生产执行能力。真实厂商、Gateway、多实例和外部环境验收必须按目标分别记录，不能由单元测试替代。
