# 文档变更同步与发布流程

官方文档的中文页面是事实权威，翻译页面是有状态的镜像。代码、Spec、项目规范和文档必须在同一次变更中保持可追踪；只改代码不改文档，或者只改翻译不复核中文来源，都不能进入发布。

## 变更触发矩阵

| 变更类型 | 必须复核的权威内容 | 必须补充的证据 |
| --- | --- | --- |
| 插件 Manifest、Binding、Assignment、Runtime、Promotion | `docs/项目规范/20260802-统一设备与工作流插件开发规范.md`、插件开发手册、插件规范差异审查 | 对应 Spec、插件代码、定向测试、成熟度状态 |
| 设备、Agent、无 Agent、Gateway、执行位置 | 设备用户指南、插件目标模式、事实来源索引 | 设备/目标代码、Spec、发现或执行测试；外部验收不足时标 `in_review` |
| 工作流 DTO、Schema、DSL、模板目录、Step、变量、SecretRef、extract/assert | `docs/项目规范/20260723-工作流模板管理及编写规范.md`、工作流开发手册 | Schema、编译器、执行器、画布转换代码和测试 |
| SSH、SFTP、SCP、CURL 或执行恢复/回滚 | 工作流执行器与恢复回滚、证书部署主链 | 执行器测试、错误边界、快照和审计证据 |
| 证书资产、Artifact、部署输入、计划、VERIFY、回滚 | 证书用户指南、部署用户指南、证书部署开发主链 | `DeploymentInputContractV1`、Snapshot、计划和执行测试 |
| 国际化资源或语言路由 | `docs/项目规范/20260707-国际化规范.md`、开发者国际化页、翻译矩阵 | `web/src/i18n`、文档 locale 配置和检查结果 |
| 主题变量或设计系统 | `docs/项目规范/20260707-主题变量规范.md`、开发者主题页 | tokens、组件、主题测试或静态检查 |
| API、Schema、数据库迁移或错误合同 | 对应开发者页、现行 Spec、事实来源索引 | 代码路径、迁移、测试和兼容性说明 |

如果变更同时命中多个行，按所有行执行，不选择其中最简单的一行代替完整复核。

## 标准同步顺序

1. **确认事实状态**：读取当前 Spec、代码、测试、项目规范和 `git status`；把未提交改动与已发布事实分开。
2. **先改合同**：行为、字段、状态或目录来源发生变化时，先更新现行 Spec 或对应项目规范；历史文件不得被改写成新事实。
3. **更新中文权威页**：同步用户操作、开发者手册、参考页、事实来源索引和状态标记。没有环境或厂商证据的能力保持 `in_review` 或 `todo`。
4. **更新翻译矩阵**：中文权威页发生事实变更时，将对应翻译标为 `needs_sync`；翻译完成后逐项复核 API 路径、字段名、状态值、错误码、权限名和安全限制，再恢复为 `current`。
5. **复核导航和链接**：新增、移动或废弃页面时同步 `.vitepress/config.mts`、语言映射和页面内链接。旧页面应保留迁移入口，不得留下指向第三套工作流样例目录的链接。
6. **执行安全检查**：删除真实 Secret、Token、私钥、密码、生产地址和未脱敏日志；示例只能使用占位符。
7. **执行验证**：至少运行文档元数据、来源、链接、编码和敏感信息检查；文档站变更还必须运行 VitePress 构建。涉及插件或工作流的代码变更必须运行对应定向测试。
8. **记录发布结论**：在 Spec 的 `tasks.md` 或验收记录中回写验证命令、提交 ID、已知缺口和恢复条件。

## 页面状态与版本规则

- `implemented` 只表示当前代码、Spec 和验证证据足以支持页面结论，不表示所有外部厂商都已验收。
- `in_review` 表示实现或草稿存在，但仍缺外部环境、协议、翻译或人工复核证据。
- `todo` 表示没有足够实现或事实依据，不能用页面存在掩盖。
- `productVersion: current` 只能描述当前代码基线；未来版本能力必须先进入 Spec 和状态记录。
- `lastVerified` 使用绝对日期；事实改变后必须更新日期和来源。

## 发布前门禁

在 `docs/Documentation` 目录执行：

```text
npm run docs:check
npm run docs:build
```

检查失败时必须修复源文件后重新执行，不能通过删除页面、关闭检查或把状态改成 `implemented` 绕过门禁。涉及工作流时还要确认模板来源只有：

- `backend/src/modules/workflow-templates/builtin-workflows`
- `data/workflows`

不得新增或恢复 `docs/工作流样例`、`docs/workflows` 等第三套来源。

## 历史页面和路径迁移

历史页面不能被静默覆盖。需要调整主题、字段或执行模型时：

1. 新建带日期的中文权威页面，或在现行页面中增加明确的迁移章节。
2. 旧页面保留历史状态和指向新页面的迁移入口。
3. 更新翻译矩阵；旧翻译如果事实过期，标记 `needs_sync`，不能继续标为 `current`。
4. 移动页面时同时更新 VitePress 导航、语言映射、正文链接和事实来源索引。
5. 删除页面前先确认没有 Spec、导航、测试报告或外部发布引用；必要时保留兼容页面。

## 需要保持公开的缺口

用户插件发布者密码学验签、Promotion 双模式归集、执行前 `configFingerprint` 复核、真实厂商部署/回滚、Gateway、产品版本、执行位置和 Citrix 不安全 TLS 的完整外部验收，都必须按真实状态记录。文档发布流程的作用是暴露这些缺口，不是把它们包装成已完成能力。
