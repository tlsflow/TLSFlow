# 自动化平台扩展与证书事件接入

## 平台模型

自动化版本现在统一由以下平台字段表达：

1. `trigger`
2. `filters`
3. `targetResolver`
4. `approvalStage`
5. `actions`
6. `guardrails`

旧自动化里的 `targetSelector` 只作为删除或作废审计输入；最新架构直接使用 `targetResolver`，运行期不得读取、转换旧字段或建立新旧双写。

## 扩展点

### Trigger

- 注册入口：`backend/src/modules/automations/application/automation-trigger-registry.ts`
- 当前内置类型：
  - `api`
  - `on_demand`
  - `once`
  - `schedule`
  - `certificate_version_created`

新增 Trigger 时必须声明：

1. 配置校验
2. 是否属于事件型 Trigger
3. 事件匹配逻辑
4. 投递幂等键生成规则

### Filter

- 注册入口：`backend/src/modules/automations/application/automation-filter-evaluator.ts`
- 当前内置字段：
  - `event.eventType`
  - `event.sourceType`
  - `event.certificateAssetId`
  - `event.certificateVersionId`
  - `event.domains`
  - `event.tags`
  - `target.certificateId`
  - `target.certificateVersionId`
  - `target.bindingId`
  - `target.assetId`
  - `target.environment`
  - `target.ownerId`
  - `target.tags`

当前内置操作符：

1. `eq`
2. `neq`
3. `in`
4. `contains_any`
5. `contains_all`

### Target Resolver

- 注册入口：`backend/src/modules/automations/application/automation-target-resolver.registry.ts`
- 当前内置类型：
  - `legacy_target_selector`
  - `certificate_version_targets`

`certificate_version_targets` 由 `backend/src/modules/automations/application/certificate-version-target-resolver.ts` 实现，围绕精确 `certificateVersionId` 反查绑定、应用资产、环境和负责人。

### Approval

- 平台实现：`backend/src/modules/automations/application/automation-approval-orchestrator.ts`
- 行为：
  1. Run 创建后、真实副作用前创建审批
  2. Run 进入 `waiting_approval`
  3. `AutomationRunCoordinator` 在恢复时轮询审批状态
  4. 审批通过后继续原 Run，不重建运行链

### Action / Executor

- 动作合同：`backend/src/modules/automations/application/automation-action-registry.ts`
- 执行器合同：`backend/src/modules/automations/application/automation-executor-registry.ts`
- 当前内置动作：
  - `create_deployment_plan`
  - `execute_deployment_plan`
  - `send_notification`

Coordinator 不再直接决定具体怎么调用部署或通知服务，而是通过注册过的执行器拿统一结果。

## 证书事件接入

### 事件发布点

- 入口：`backend/src/modules/certificates/application/certificates.application-service.ts`
- 行为：证书新版本成功入库后，发布 `certificate.version.created`

事件摘要只保留受控字段：

1. `tenantId`
2. `eventId`
3. `certificateAssetId`
4. `certificateVersionId`
5. `sourceType`
6. `domains`
7. `tags`
8. `occurredAt`

禁止把证书明文、私钥、SecretRef 解密结果或制品内容写进自动化事实。

### 投递与消费

- 投递服务：`backend/src/modules/automations/application/automation-event-delivery.service.ts`
- 统一任务类型：`AUTOMATION_TRIGGER_DELIVERY`

流程：

1. 证书模块发布事件
2. 自动化平台为命中的活动自动化创建 `automation_trigger_deliveries`
3. 统一任务 Worker 消费投递
4. 通过 Trigger / Filter / Resolver 创建 Run
5. 若需要审批则进入 `waiting_approval`
6. 审批通过后继续执行 `create_deployment_plan -> execute_deployment_plan`

## 精确版本约束

证书场景的关键约束不是“部署最新版本”，而是“部署这次事件对应的精确版本”。

因此：

1. Run 的 `triggerContext.certificateVersionId` 必须固定
2. RunTarget 的 `targetSnapshot.certificateVersionId` 必须固定
3. `create_deployment_plan` 必须优先使用该精确版本
4. 审批恢复后不得重新查询 `latest`

## 新增场景的接入顺序

1. 先定义事件或手动触发事实
2. 为事件字段注册 Filter accessor
3. 实现新的 Target Resolver
4. 如有副作用，注册 Action / Executor
5. 如有审批，复用平台 `approvalStage`
6. 补齐 Delivery、Run、RunTarget、ActionResult 定向测试

如果某个新场景需要在 Coordinator、Controller 或 Editor 里再堆 if/else，说明扩展点设计还没接对。
