# Workflow executors, recovery, and rollback

## Steps and stages

Current Step types include `http`, `ssh`, `sftp`, `scp`, `condition`, `transform`, `foreach`, `checkpoint`, `checkpoint_verify`, `wait`, and `manual`.

Certificate-deployment stages are fixed as:

```text
prepare -> backup -> install -> refresh -> verify
```

`stage` is a business phase for plans and audit, not a new Step type. `rollback` is an independent array in the same WorkflowVersion; do not append rollback steps to the main flow or maintain a second DSL.

## HTTP/CURL

An HTTP Step obtains its connection through the Contract `connectionRef`. Basic, bearer, API-key, cookie, custom-header, and mTLS authentication use controlled Secrets. `extract` can capture JSON Path, response path, header, regular-expression, status-code, or text results. `assert` can check status code, JSON Path, header, text, regular expression, or certificate fingerprint.

URLs are HTTP(S) only, and cleartext HTTP is rejected by default. `tls.verify=false` requires `allowInsecure=true` plus approval, audit, isolated testing, and a publication gate. The CURL executor owns retries, idempotency keys, response limits, redaction, and structured errors.

## SSH, SFTP, and SCP

SSH Command Steps use `connectionRef` and a Credential slot. Host Key policy must be explicit: strict verification, first-use trust, or manual approval. File transfer uses an Artifact or controlled content reference. Upload to a temporary path, verify size or hash, then atomically replace the target where supported.

File permissions, owner, group, remote path, expected hash, and timeout belong in the plan and audit. Scripts, private keys, passwords, and certificate material must not enter template text or ordinary logs.

## foreach and checkpoints

`extract` produces Step output; sensitive output is marked sensitive and redacted. A failed `assert` blocks false success and preserves the assertion result. `foreach` declares an items path, element variable, child Steps, and a maximum of 1000 items with at most three nesting levels. Only read-only discovery may use `continueOnError`.

Before formal execution, the host creates a recovery ledger, resource locks, and required Execution Grants. Each successful Step is recorded, and its Grant is reclaimed after the Step ends. Only idempotent Steps may recover automatically; a running non-idempotent Step requires manual handling or explicit compensation.

Recovery and rollback reuse the fixed WorkflowVersion and input snapshot, validate checkpoints and locks, execute the declared rollback array, and preserve original failure, rollback result, and final verification.

## Maturity boundary

Structured SSH/SFTP/SCP/CURL executors and workflow tests have code evidence. Windows Remote remains at a planning/mock boundary. Real vendor, Gateway, multi-instance, and external-environment acceptance must be recorded separately.
