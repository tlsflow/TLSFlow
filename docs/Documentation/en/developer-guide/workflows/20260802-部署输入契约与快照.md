# Deployment input contract and snapshots

## The Contract is the only input declaration

Workflows and Agent Plugins share `DeploymentInputContractV1`. It declares four slot groups:

| Slot | Content | Typical use |
| --- | --- | --- |
| `variables` | Ordinary variables | Service name, path, port, target identifier |
| `connections` | HTTP/SSH connection fields | Host, port, user, TLS, or Host Key |
| `credentials` | Credential slots | Username/password, SSH key, bearer credential, API credential, client certificate |
| `artifacts` | Artifact slots | Leaf certificate, private key, intermediate chain, PFX, or another file |

Ordinary variables do not contain `credential` or `certificate` types. Certificate material enters an executor only through an Artifact slot, never through an ordinary variable, DSL command, log, or plan JSON.

## Source and override rules

Ordinary variables and connection fields must declare `source`, `lifecycle`, `bindingPolicy`, and `configurationMode`. Effective values resolve across execution overrides, application assets, managed targets, device assets, and plugin defaults. Discovered asset facts take precedence over defaults; a fixed field cannot be overridden during execution.

## Resolved input

Runtime accepts only `ResolvedDeploymentInputV1`, including `assetContext`, variables, connections, credentials, artifacts, provenance, sensitive paths, issues, `executable`, and `resolvedSha256`.

The resolver has `configure`, `save`, `preflight`, and `execute` phases. A non-executable result or blocking issue must fail closed before a DSL Step, Agent, Gateway, SSH, or HTTP call.

Without runtime-injected values or Step outputs, `preflight` and `execute` must produce the same `resolvedSha256`. Executors must not merge old user, asset, or parallel Credential fields on their own.

## Credentials, Artifacts, and snapshots

Credential bindings store only stable `credentialId` values. Planning fixes the Credential version and a redacted snapshot; runtime resolves the exact SecretRef through a short-lived Secret Grant.

Artifact bindings store identity, output slot, digest, and sensitivity. Private keys, PFX passwords, and PFX content are available only through a controlled Artifact Grant and are reclaimed promptly.

`DeploymentInputSnapshotV1` fixes the execution identity, redacted context, provenance, sensitive paths, issues, `executable`, `resolvedSha256`, snapshot ID, revision, and hash references. Retries must validate the snapshot, target identity, and hashes; they must not re-read current configuration. The `configFingerprint` comparison before execution remains `TODO`.
