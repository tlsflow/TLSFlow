# 自动化、设置与凭据

## 自动化配置

自动化编辑器现在按统一平台模型配置，而不是旧版“处理哪些证书 / 什么时候更新 / 执行安全控制”的三段式壳子。

当前配置顺序固定为：

1. 触发器
2. 执行
3. 条件与安全

### 触发器

当前支持以下触发方式：

1. 外部 API 触发
2. 固定时间执行一次
3. 定期执行
4. 证书新版本事件

证书新版本事件适用于以下事实：

1. ACME 自动续签成功后生成新版本
2. 手工导入证书后生成新版本

管理员可以进一步限制事件来源，只接收：

1. `ACME`
2. `手工导入`

### 执行

执行步骤定义“命中后到底更新哪些应用资产”，而不是绑定某个历史 DeploymentPlan。

当前支持两种更新范围：

1. 更新关联的全部应用资产
2. 只更新指定应用资产

含义如下：

1. 选择“更新关联的全部应用资产”时，系统按证书绑定和部署能力自动解析所有关联资产。
2. 选择“只更新指定应用资产”时，系统只会对手工选中的应用资产创建并执行 DeploymentPlan。

这两个范围都可以继续叠加后面的条件过滤，不是二选一后就失去筛选能力。

### 条件与安全

条件步骤负责收窄命中范围，并定义执行护栏。当前可配置项包括：

1. 证书域名
2. 证书标签
3. 目标环境
4. 目标负责人
5. 指定证书版本（仅非事件型自动化）
6. 单次最大目标数
7. 并发数
8. Dry Run 要求
9. 审批要求
10. 失败阈值

证书新版本事件场景有两个关键边界：

1. 运行时固定部署触发事件中的精确 `certificateVersionId`，不会漂移到后续版本。
2. 如果配置审批，审批通过后恢复原 Run，仍然继续使用这次事件冻结的目标与版本快照。

### 证书新版本自动化

当前自动化已经支持“证书新版本事件”场景，适用于：

1. ACME 自动续签成功后产生新版本
2. 手工导入证书后产生新版本

典型流程：

1. 新证书版本入库
2. 命中自动化规则
3. 解析关联证书绑定和应用资产
4. 如配置要求则进入审批
5. 审批通过后创建并执行 DeploymentPlan

其中目标解析规则如下：

1. 默认解析事件对应证书所关联的全部可部署应用资产。
2. 如果在执行步骤手工指定了应用资产，则只在指定资产范围内继续运行。
3. 如果还配置了域名、标签、环境、负责人等条件，系统会在目标预览和真实运行中使用同一套过滤规则。

运行详情页会展示：

1. 触发来源
2. 精确证书版本 ID
3. 审批 ID
4. 投递 ID
5. 排除原因汇总

自动化不会部署“当时最新版本”，而是固定部署触发事件对应的精确 `certificateVersionId`。如果某个目标因为缺少绑定、缺少部署能力或不满足过滤条件被排除，运行详情会保留稳定的排除原因。

## 凭据管理

全局凭据只保存稳定引用和版本信息。部署计划固定使用的凭据版本，不能因为当前凭据轮换而改变历史计划。

当前稳定基线没有独立通用系统配置模块，文档只描述已经存在的通知设置、凭据和管理入口。
