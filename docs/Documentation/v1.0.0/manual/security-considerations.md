# 安全注意事项

这是一份日常使用清单，帮助管理员在登录、接入设备、部署证书和处理故障时减少高风险操作。它不替代组织的安全策略、密钥保管制度或应急预案。

## 账号和权限

- 每个人使用自己的账号，不共享管理员账号。这样审计记录才能准确对应责任人。
- 按岗位授予完成工作所需的最小权限。用户、角色、凭据、插件、审批和部署执行尽量由不同岗位负责。
- 人员离职或职责变化时，先移除角色和组成员，再禁用账号；到“日志审计”确认变更已经记录。
- 菜单是否显示不能代表真实授权。请使用实际岗位账号验证查看证书、编辑资产、审批部署和导出审计证据等关键操作。

## Secret 和证书

- 密码、API Token、SSH 私钥、客户端证书、PFX/JKS 密码和 Webhook 密钥统一保存到“系统设置 → 凭据”，业务页面只引用凭据档案。
- 不要把 Secret 写入备注、工作流说明、截图、聊天或普通日志。页面显示的敏感值应始终保持脱敏。
- 凭据轮换后，通知引用它的设备、云账号和自动化负责人，并逐项更新引用和测试连接。
- 临时共享使用短有效期或一次性凭据，用完立即撤销；不要通过聊天工具传递长期密码。

## 网络和远程连接

- 生产环境使用 HTTPS，并限制管理页面和 API 的访问范围。
- 不要把 Backend、Browser Runtime、TLS Inspector 或内部调试端口直接暴露到公网。
- 按网络策略放行目标主机、Webhook 和 DNS 服务。临时排查可以记录例外，但不要长期关闭证书校验。
- 连接异常时先确认目标服务的真实状态，再决定重试、补偿或回滚，避免重复执行。

## 审计、备份和异常处理

1. 定期检查“日志审计”和执行记录，确认登录、权限变更、凭据使用、审批、部署和回滚都有责任人。
2. 备份数据库、工作流、插件和恢复所需的加密密钥；在隔离环境定期演练恢复，并限制备份文件访问。
3. 发现 Secret、备份或导出文件泄露时，立即按组织流程轮换相关密钥并保留审计证据。
4. 发生部署失败或外部连接超时时，记录租户、计划编号、运行编号和时间，再到执行记录、监控和审计页面交叉核对。
