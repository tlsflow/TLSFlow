# 自动化

自动化用于创建按规则自动执行的证书更新计划。它只处理已经接入、具备证书绑定和可用部署目标的应用资产，不负责第一次安装证书或新增应用。需要立即为单个应用更新证书时，请回到“资产中心 → 应用”点击该应用的“部署更新”，不要从本页开始。

## 新建自动化

开始前请确认：证书已经导入并有可用版本，应用资产已经添加，且目标应用已经绑定证书。然后进入“证书部署 → 自动化”，点击“新建自动化”。表单分为三步，填写过程中可以用“上一步”“下一步”返回检查。

### 第一步：选择触发方式

1. 在“触发器”下拉框中选择证书新版本、一次性、周期、按需或 API 触发。
2. 按页面提示填写触发时间、周期或证书事件来源。
3. 点击“下一步”。


### 第二步：确定更新范围

1. 在“证书域名”中勾选需要处理的域名。域名来自已登记的证书资产；如果列表为空，先回到证书管理导入证书。
2. 选择“更新关联的全部应用资产”，让系统在运行时找出该域名下所有已绑定目标；或选择“只更新指定应用资产”，从“可选资产”勾选目标后点击“添加”。
3. 如需调整范围，在“已选资产”中勾选目标并点击“移除”，也可以点击“清空”重新选择。选择指定资产时至少保留一个目标。
4. 查看页面下方的执行能力提示，确认这些目标具备可用的部署方式，再点击“下一步”。


### 第三步：设置执行安全控制

1. 填写容易识别的自动化名称；说明可写明负责的业务、环境和维护窗口。
2. 设置“并发数”。数值越大，同时处理的应用越多，但对目标系统的压力也越大，建议从较小数值开始。
3. 设置“失败数量阈值”。失败达到该数量后，系统会停止继续扩散，便于先处理问题目标。
4. 按组织流程决定是否勾选“执行前必须审批”。生产环境建议保留审批。
5. 阅读“配置摘要”，确认触发方式、域名和目标范围无误后点击“保存”。


## 管理自动化

保存后，在列表中可以执行以下操作：

- “详情”：查看当前状态、证书域名、目标范围、版本策略、并发和审批设置。
- “编辑”：修改规则，保存后生成新的配置版本。
- “复制”：以现有规则为基础新建一条规则，适合创建测试环境副本。
- “启用/停用”：控制是否允许该规则继续被运行。
- “运行历史”：查看每次运行的整体进度和每个目标的处理结果。
- “删除”：删除不再使用的规则。删除前请确认没有待处理的维护任务。


## 查看运行结果

打开某次运行后，可以看到触发来源、实际使用的证书版本、审批状态、失败阶段和目标快照。展开目标明细可查看当前动作、失败原因及对应的部署计划或执行记录入口。目标被排除通常表示没有绑定、目标不可部署、环境不匹配、权限不足或目标已经是同等有效期；请修正源数据后重新运行，不要手工改写运行结果。

审批暂停后恢复时，系统继续使用本次运行已经确定的目标和证书版本，不会自动改用后来新增的版本。通知投递失败和证书部署结果分别记录，通知失败不会撤销已经完成的部署。


## 使用时的注意事项

- 先用少量测试目标验证，再扩大到生产范围。
- 证书版本和目标范围是运行开始时确定的，执行过程中不要临时替换证书或绑定。
- 生产环境建议启用审批并设置合理的失败阈值，避免单个目标异常造成大范围变更。
- 运行显示“未知”或外部写入超时时，不要立即重复执行；先在执行记录和审计中确认目标实际状态。
