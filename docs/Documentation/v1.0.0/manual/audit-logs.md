# 日志审计

日志审计用于回答“谁在什么时候对什么对象做了什么操作，以及结果如何”。记录适合日常复核、权限追踪和问题交接。

## 查看审计记录

1. 进入“日志审计”。页面顶部先显示记录总数、失败/拒绝数量和用户操作数量，帮助判断近期是否有异常。
2. 在记录列表中按时间倒序查看最新事件。每条记录会显示结果状态、易读的操作标题、事件类型、摘要和发生时间。
3. 点击“刷新”重新读取最新记录。遇到刚完成的部署、审批或权限变更时，刷新后再核对。
4. 重点关注“失败”“拒绝”等状态，并记录事件摘要中提供的对象名称、操作人和关联编号，便于联系责任人或继续查看执行详情。

截图占位：日志审计页面，展示顶部三项统计卡片、成功/失败状态标签、操作摘要和本地时间。

## 导出操作证据

1. 点击页面右上角“导出操作证据”。
2. 等待页面返回导出结果；如果出现失败提示，先记录提示中的请求编号，再联系管理员处理。
3. 导出的内容用于审计留档和问题交接，建议与对应的部署计划、执行记录或报表一并保存。

截图占位：日志审计页面右上角“导出操作证据”按钮及导出失败提示位置。

## 常见核对场景

- **登录与会话**：核对登录成功、登录失败和退出时间，确认账号使用符合值班安排。
- **权限和审批**：核对角色调整、权限拒绝、审批创建、通过或驳回，确认变更是否经过授权。
- **证书和部署**：核对证书导入、创建部署计划、执行部署和请求回滚，确认操作人与业务工单一致。
- **插件和工作流**：核对插件安装、权限拒绝和工作流执行，确认使用的是批准过的能力。
- **通知与自动化**：结合自动化运行和通知投递记录，确认失败究竟发生在目标选择、部署执行还是消息发送。

排查时把执行记录中的计划编号、运行编号与审计摘要中的关联编号放在一起核对，不要只根据单条日志做结论。

## 安全与隐私提示

审计记录只提供查看证据，不提供编辑或删除入口。凭据、私钥、令牌和 Secret 只显示脱敏信息，不要把审计截图当作凭据备份。
