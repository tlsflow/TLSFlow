# 通知

通知用于把证书状态、续期结果、报表和绑定漂移等事件发送给值班人员。进入“系统设置 → 通知”后，可在“事件”“模板”“渠道”“投递记录”四个页签之间切换。

## 推荐配置顺序

1. 先在“渠道”创建并测试发送渠道。
2. 在“模板”确认消息标题、正文和变量；需要自定义时再创建或编辑模板。
3. 回到“事件”，为需要关注的事件选择模板和渠道，并启用路由。
4. 在“投递记录”检查实际投递状态。通知成功只表示消息已交给渠道，部署结果仍需到执行记录核对。


## 配置发送渠道

1. 打开“渠道”页签，选择“新建通知渠道”，填写名称和类型：Email、企业微信、飞书、钉钉、Slack、Telegram 或通用 Webhook。
2. 根据类型填写连接信息：
   - **Email**：SMTP 主机、端口、发件地址和 STARTTLS/SSL-TLS；用户名和密码必须同时填写或同时留空。
   - **企业微信、飞书、钉钉、Slack**：机器人 Webhook；飞书和钉钉可选填签名密钥。
   - **Telegram**：Bot Token、Chat ID，可选填消息主题（Topic）ID。
   - **通用 Webhook**：完整 URL、POST/PUT/PATCH 方法，可选填 JSON 请求头和签名密钥。
3. 企业微信、飞书或钉钉使用私有化平台时，在对应字段填写受信任的 HTTPS Origin（例如 `https://notify.example.internal`）。这里只填写协议、主机和可选端口，不要粘贴完整机器人 URL。
4. 选择“确认创建”。密码、Token、Webhook 和签名密钥会作为 Secret 加密保存，之后不会再次显示明文。
5. 在渠道卡片选择“测试”。Email 测试需要填写收件地址；其他渠道使用已保存的目标。确认收到测试消息后，再启用事件路由。


## 配置事件路由

1. 打开“事件”页签，选择要配置的证书事件，例如续期结果、证书状态、报表、到期预警、已过期、已吊销、绑定漂移或报表失败。
2. 选择“配置”或“编辑”，填写路由名称、已测试的渠道、模板和优先级。优先级用于多个路由同时匹配时的处理顺序，请按组织约定填写。
3. 选择“确认创建”保存。返回事件列表，确认模板、渠道和状态均正确。
4. 维护窗口或临时停用时，选择“停用”；恢复发送前选择“启用”。当前页面没有单独的静默规则，需通过停用事件路由或渠道完成控制。


## 编辑和预览模板

在“模板”页签选择“新建通知模板”或“编辑”，填写稳定的模板键、标题模板和正文模板。变量使用 `{{variable}}` 格式；保存前检查页面显示的必需变量，并选择“预览”确认内容在手机端也易读。模板停用后，引用它的路由不会发送该模板消息。


## 查看投递和处理失败

1. 打开“投递记录”，按全部、失败、重试中、排队或已送达筛选。
2. 查看事件类型、渠道、模板、尝试次数、失败分类和下次尝试时间。时间按浏览器本地时间显示。
3. 打开“详情”查看每次尝试和 outbox（待发送队列）记录；确认是网络不可达、Secret 失效还是对方服务拒绝。
4. 修复配置后，对失败记录选择“重试”。不要因通知失败而重复创建证书部署任务，部署结果应在执行记录中单独确认。


## 安全提示

Webhook URL、Bot Token、SMTP 密码和签名密钥都属于敏感信息，只能填写到对应 Secret 输入框。不要把它们写进模板、备注、工单或截图。私有化平台地址必须使用受信任的 HTTPS Origin，并在测试成功后再启用生产路由。
