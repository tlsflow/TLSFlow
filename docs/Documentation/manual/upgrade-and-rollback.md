# 升级与回滚

平台升级、Agent 升级和证书部署回滚是三件不同的操作。执行前先确认维护窗口、备份和验收人员，不要把某一类回滚当成另一类回滚。

## 升级前检查

1. 记录当前平台版本、Agent 版本、已发布工作流版本和正在运行的任务。
2. 完成平台数据、工作流、用户插件和密钥材料备份，并确认备份可读取。
3. 在测试环境或低风险目标上先验证目标版本，确认许可证、插件和只读发现正常。
4. 通知相关业务负责人，暂停可能与升级冲突的自动化运行和证书变更。

截图占位：升级前检查清单，展示当前版本、备份完成、运行任务和维护窗口确认项。

## 平台升级

1. 按目标版本准备平台镜像和配置，版本标签以发布包提供的版本为准。
2. 维护窗口内按运维方案启动平台服务，等待页面或运维记录确认升级完成。
3. 登录控制台检查版本信息、许可证状态、插件市场和只读发现。
4. 在测试目标上执行一次 Dry Run，确认输入、权限和执行通道均可用后，再恢复生产写操作。
5. 观察一段时间的登录、监控、通知和执行记录，确认没有新增异常。

升级失败时立即停止继续升级，保留升级记录和原始备份。不要在未确认兼容性前切回旧版本。

截图占位：升级后的系统设置/版本信息和测试 Dry Run 结果。

## 平台回退

当前版本没有通用的“一键平台回滚”按钮。发布回退需要由运维人员：

1. 停止新版本并保留日志、备份和原 `data/` 目录。
2. 确认备份与目标旧版本兼容后，恢复对应的数据库、工作流、运行时、TLS Inspector 和插件目录。
3. 使用匹配旧版本的镜像和原密钥启动，检查迁移、租户、许可证和只读发现。
4. 在测试目标完成读取和 Dry Run 验证，再恢复生产写操作。

截图占位：平台回退验收记录，展示旧版本启动、数据恢复和测试验证结果。

## Agent 升级

1. 在设备详情中查看当前 Agent 版本和可用升级提示。
2. 点击“升级”后核对目标设备、当前版本和目标版本，确认维护窗口内可以重启或短暂中断服务。
3. 确认升级计划，提交升级事务并记录事务编号。
4. 根据事务编号查看传输、安装和重启状态；升级过程中不要重复提交同一设备的升级。
5. 完成后刷新设备详情，确认 Agent 在线、版本已更新、心跳正常，再恢复自动化任务。

截图占位：Agent 升级确认窗口，展示目标设备、当前版本、目标版本和升级注意事项。

是否支持自动回退取决于该 Agent 发布包，不能假设任意历史版本都能直接回退。

## 证书部署回滚

只有部署计划声明了备份清单和回滚步骤时，才在执行详情中发起证书回滚。回滚后重新检查目标服务是否正常、TLS 握手是否成功、站点是否使用预期证书，并保留原始失败和回滚结果。没有备份清单时，不要自行覆盖远端证书文件。
