# 故障排查

按以下顺序收集证据，避免先改配置再猜原因：

1. 记录租户、操作者、页面地址、任务/计划 ID 和请求 ID。
2. 检查容器状态、数据库健康检查、Backend 日志和浏览器控制台错误。
3. 对设备检查 Agent 心跳、连接测试、发现状态、插件版本和执行位置。
4. 对部署检查输入投影、凭据/Artifact Grant、Dry Run、审批和快照摘要。
5. 打开执行步骤和“日志审计”对照失败原因；外部写请求超时先按 UNKNOWN 处理，不要自动重放。
6. 只有记录存在恢复清单时才回滚；回滚后再次做目标和 TLS 回读。

常见现象：端口错误先确认标准 Web `8080` 与 Backend `3003` 的区别；登录失败检查初始化密码和令牌密钥；菜单缺失检查租户角色；插件不可用检查版本状态、权限和兼容目标。

排障时不要直接编辑数据库、快照或执行记录。`RUNNING` 任务不能靠重复点击改变状态；草稿可以删除，已发布或已执行计划必须保留。文档状态 `implemented`、`in_review` 和 `todo` 是文档治理标记，不是控制台业务状态。
