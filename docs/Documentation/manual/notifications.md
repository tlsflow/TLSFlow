# 通知

通知管理用于配置消息发送渠道、决定哪些事件发送到哪里、统一消息样式，并在维护窗口暂时静默。进入“系统设置 → 通知”后，可在“通知渠道”“投递记录”“规则与模板”三个页签之间切换。

## 配置私有化平台地址

企业微信、飞书或钉钉使用私有化部署时，先在页面顶部对应的私有化 Origin 文本框中填写允许访问的地址，每行一个，例如 `https://notify.example.internal`，然后点击“保存设置”。这里只填写协议、主机和可选端口，不要填写路径、查询参数、账号信息或完整机器人 URL。没有先加入白名单时，后续测试和投递会被拒绝。

截图占位：通知管理页面顶部“私有化平台地址”设置区，展示三个 Origin 输入框和“保存设置”按钮。

## 新建和测试通知渠道

1. 在“通知渠道”页签点击“新建通知渠道”，填写渠道名称并选择类型：Email、企业微信、飞书、钉钉、Slack、Telegram 或通用 Webhook。
2. 按渠道类型填写必需信息：
   - **Email**：SMTP 主机、端口、发件地址、连接加密方式；用户名和密码需同时填写。
   - **企业微信/飞书/钉钉/Slack**：粘贴对应机器人 Webhook；飞书和钉钉如启用加签，再填写签名密钥；选择私有化部署时先完成 Origin 白名单。
   - **Telegram**：填写 Bot Token、Chat ID，可选填 Topic ID。
   - **通用 Webhook**：填写完整 URL、HTTP 方法（POST、PUT 或 PATCH），需要固定请求头时输入合法 JSON，可选填签名密钥。
3. 点击“确认创建”。密文输入框中的 Token、密码和签名密钥会加密保存，创建后不会再次明文显示，请在提交前确认无误。
4. 在渠道卡片中点击“测试”。Email 测试需要填写收件地址，其他渠道使用已配置的目标。确认收到测试消息后再启用业务路由。
5. 需要暂时停用某个渠道时点击“停用”；恢复发送前点击“启用”。

截图占位：新建通知渠道窗口，展示类型选择、按类型变化的字段、密文输入提示和“确认创建”。

## 创建通知路由

1. 切换到“规则与模板”，点击“新建通知路由”。
2. 填写路由名称，选择已经测试成功的通知渠道。
3. 填写事件来源，决定接收哪些事件；设置路由优先级，数字越符合组织约定越应优先处理。
4. 设置去重窗口（秒），避免同一事件在短时间内重复发送。
5. 点击“确认创建”，然后在路由列表检查状态和关联渠道。

截图占位：新建通知路由窗口，展示名称、渠道、事件来源、优先级和去重窗口。

## 自定义模板和静默规则

### 通知模板

点击“新建通知模板”，填写模板键、标题模板和正文模板。模板键应保持稳定，便于后续路由复用；保存前检查标题和正文在手机端也能读懂。

### 静默规则

1. 点击“新建静默规则”，填写名称和静默原因。
2. 填写事件来源以及开始时间、结束时间，时间使用浏览器本地时间。
3. 保存后在列表确认规则状态和生效区间。维护窗口结束后，通知会恢复正常投递。

截图占位：规则与模板页签，展示通知模板列表和静默规则的生效时间。

## 查看投递并处理失败

1. 切换到“投递记录”，按渠道查看最近投递状态、请求编号、延迟和失败分类。
2. 对失败记录先检查请求编号、响应状态和重试次数，确认是地址不可达、凭据失效还是对方服务拒绝。
3. 修复网络、机器人配置或密文后，点击“重新投递”。不要因为通知失败而重复创建证书部署任务，证书部署结果需要在执行记录中单独核对。
4. 通知投递成功只代表消息已交给目标渠道，不代表收件人已经阅读；重要变更仍应在业务工单中留痕。

截图占位：投递记录列表，展示成功/失败状态、请求编号、失败分类和“重新投递”按钮。

## 安全提示

Webhook URL、Bot Token、SMTP 密码和签名密钥都属于敏感信息，只粘贴到对应密文输入框，不要写进通知模板或截图。私有化地址必须是受信任的 HTTPS Origin；测试成功后再启用路由，避免错误配置向真实用户发送测试内容。
