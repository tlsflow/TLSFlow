# 租户与 RBAC

租户是业务数据、人员和权限的隔离边界；角色决定人员在租户内能看什么、改什么和执行什么。多租户场景下，每个租户都应有独立的账号、角色和凭据。

## 推荐的初始化顺序

1. 使用初始管理员登录后，确认页面显示的是要管理的租户。
2. 进入“系统设置 → 角色”，按岗位创建只包含必要范围的角色，例如证书查看、证书操作、审批和审计查看。
3. 进入“系统设置 → 用户”，为日常操作人员创建本地账号或绑定身份源账号，再分配对应角色。
4. 如需按团队授权，先在“用户 → 组”创建组，再在角色详情中把组加入角色。
5. 使用一个非管理员账号登录，分别验证证书查看、应用资产管理、部署审批和日志查看是否符合岗位预期。

## 处理租户结构

具有相应管理权限的管理员可在“系统设置 → 租户架构”查看当前是单租户还是分层租户模式。切换模式前先运行页面提供的检查，逐项处理阻塞项；只有检查通过后再确认启用。分层模式下可新增公司节点、指定管理员并暂停或恢复公司节点。此类操作会影响整组人员和资源，建议安排维护窗口并保留审批记录。

## 权限使用原则

- 同一人员可以拥有多个角色，最终可用范围取所有授权和拒绝规则的共同结果。
- 菜单是否显示只反映当前账号可见入口，不能替代权限检查；用实际业务账号验证才算完成。
- 证书私密材料、凭据管理、插件启用、审批和部署执行应由不同岗位负责，避免一个账号拥有全部高风险操作。
- 角色、租户成员或账号状态改变后，让相关人员重新登录，并到“日志审计”确认变更已经记录。
