# 故障排查

遇到问题时先记录事实，再按顺序定位。不要一开始就改配置、重复点击或重新创建任务，否则可能掩盖真正原因。

## 第一步：记录可追踪信息

在工单或交接记录中写下租户、操作者、页面地址、发生时间、任务编号/计划编号、运行编号和请求编号。截图时遮挡密码、Token、私钥和完整 Webhook URL。

截图占位：问题页面的错误提示，突出请求编号、任务编号或计划编号，敏感信息已遮挡。

## 第二步：按对象分类检查

### 登录或菜单异常

- 登录失败：确认使用的是管理员分配的账号和当前初始化密码，检查令牌是否过期；不要反复刷新造成更多失败记录。
- 菜单缺失或按钮不可用：请管理员确认当前租户、角色和操作权限。看不到按钮通常是权限限制，不是页面损坏。
- 页面显示服务请求失败：记录请求编号和错误提示，再刷新一次确认是否为临时网络问题。

### 应用资产或设备异常

- 查看设备详情中的 Agent 在线状态、最后心跳、连接测试和发现状态。
- 检查设备上的插件版本是否处于启用状态，并确认该插件支持目标平台。
- 确认执行位置和目标地址正确；网络设备或隔离区目标需要使用组织批准的网关路径。

### 证书部署异常

1. 打开执行记录，确认失败发生在目标选择、计划创建、预检、审批、执行、验证、回滚还是通知阶段。
2. 检查证书版本、目标绑定、凭据授权和 Dry Run 摘要是否匹配本次任务。
3. 将计划编号、运行编号与“日志审计”中的操作记录对照，确认操作人和时间。
4. 外部写入超时或显示“结果未知”时，先回读目标站点的实际证书和服务状态；在确认前不要自动重放，避免重复变更。

截图占位：执行记录详情，展示步骤状态、失败阶段、错误摘要和计划/运行编号。

## 第三步：安全恢复

只有执行计划明确提供备份清单和回滚步骤时，才使用“回滚”。回滚完成后重新检查目标服务、TLS 证书和应用可访问性，并把原始失败、回滚结果和远端路径一并留档。没有恢复清单时不要自行覆盖远端文件。

## 常见提示速查

- **地址或端口错误**：确认使用的是管理员提供的控制台地址和服务地址，避免把后台接口地址当成用户登录地址。
- **插件不可用**：检查插件版本状态、当前账号权限和目标兼容性，不要直接改数据库中的插件记录。
- **任务一直运行**：先查看执行步骤和设备心跳；运行中的任务不能靠重复点击改变状态。
- **通知失败**：到“系统设置 → 通知”查看投递请求编号和失败分类，修复渠道后再重新投递。
- **监控异常**：先刷新并重新检测，比较探测历史；单次超时不等于持续故障。

## 禁止操作

排障时不要直接编辑数据库、运行快照或执行记录。草稿可以按页面提供的删除入口处理，已发布或已执行计划必须保留。页面上的文档状态提示只用于内容维护，不代表控制台业务状态。
